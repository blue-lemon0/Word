## 0. 立场

**重点不是词库有多大，是系统有多灵活。**

词库可以只有 2998 词，甚至只有 300 词。只要「不够就加、多了就删、不对就改」没有摩擦，
它就能用一辈子。所以本文档里**所有设计决策的判据都是：是否让编辑变便宜**。

例句 3 句还是 5 句——不重要，因为随时能改。
词库 2998 还是 6000——不重要，因为随时能加。
**唯一重要的是：改起来要顺手。**

## 1. 核心模型：义项是一等实体

这是整个设计的地基。

```
词（word）  ＝ 名词，"crime"
  └─ 义项（sense） ＝ 可独立学习、可独立编辑的单位
       ├─ id        内部稳定标识，永不变
       ├─ gloss     中文释义
       ├─ glossEn   英文释义
       ├─ pos       词性
       ├─ sentences 例句
       └─ note      备注
```

**关键设计：`sense.id` 与 `sense.slot` 分离。**

```
sense.id   = "s1"  但它其实是个内部 UUID（如 "a7f3"），永不变
sense.slot =  1     显示用编号（s1/s2/s3），可重排、可删、可插
```

为什么分离：

| 操作 | slot 变化 | id 不变 → 学习进度 |
|---|---|---|
| 在 s1 前面插入新义项 | s1→s2, 新增 s1 | **自动跟着义项走** |
| 删除 s2 | s3→s2 | **自动跟着走** |
| 调整顺序 | 全变 | **自动跟着走** |
| 改中文释义 | 不变 | 不变 |

如果用 `senseId` 直接当主键，**插入一个义项会让后面所有义项的编号漂移，
学习进度全乱**。这是现有 schema 的真实缺陷。

例句和学习状态都挂在 `sense.id` 上，**跟显示编号解耦**。

## 2. 功能清单

### A. 内容编辑（最高优先级）

#### A1 义项的增删改合
```
新增义项     任意位置插入，不必追加到末尾
删除义项     软删除（进回收站），可撤销 30 天
合并义项     s2+s3 → s1，合并 sentences/note/学习状态（两边的都对）
拆分义项     一条拆成两条，句子让用户选归属哪边
重排         拖拽排序
```

**为什么合并要合并学习状态**：用户在 s2 上背了 20 次，合并进 s1 之后那 20 次应该计入 s1，
否则他的真实掌握度就丢了。这是「灵活」的一部分——改结构不该毁掉已有积累。

#### A2 字段就地编辑
所有字段点开即改，不跳页、不弹窗确认、不进二级页面。

```
gloss        中间形态，接受未完成的输入，失焦才校验
glossEn      同上
pos          下拉选择（n./v./a./adv./vi./vt./prep./conj…）
sentences    列表，行内编辑，支持拖拽排序
note         多行文本，常用内容做成快捷插入（如「关键：受法律惩罚」）
```

#### A3 批量操作
从阅读里攒 20 个生词是常态。单条编辑撑不住。

```
批量选词 → 批量设置 tier / trap / 批量删除 / 批量导入 JSON
批量改义项：选中多个义项 → 批量补 sentences / 批量改 pos
```

### B. 导入

#### B1 粘贴导入：不只是补例句
AI 返回的 JSON 可能：
```
· 只补了例句          → 最常见
· 修正了我的中文释义   → AI 查了翻译软件，可能比我准
· 多给了一个义项      → AI 发现我漏了
· 拆成了两个义项      → AI 认为该分开
· 完全重写            → AI 的划分方式不同
```

**所以导入不是一个「填表」，是「合并两个版本」。**

三种模式，但**默认值按内容自动选**：

| 情况 | 默认动作 | 用户可改 |
|---|---|---|
| 本地义项 id 在导入里存在 | 逐条对比，缺什么补什么 | 逐条选：保留本地/用导入的/合并 |
| 本地有、导入没有 | 保留本地，不动 | 可选删除 |
| 导入有、本地没有 | 追加为新义项 | 可选丢弃 |
| 同义项但内容不同 | **弹出对比，让用户选** | 强制选择，不默认 |

**不搞 merge/replace 二选一**——那是懒人设计，会丢数据。

#### B2 导入校验
```
必过（不通过则整份拒绝）：
  · word 合法
  · 每条义项 gloss 非空
  · 同一词内无两条 glossEn 完全相同   ← 重复卡片
  · sentences[].en 非空
  · id 冲突时内容不一致 → 弹出对比而非拒绝

警告（接受但提示）：
  · 某义项只有中文无英文
  · 某义项 0 例句
  · 例句中未出现该词
```

### C. 学习状态与内容分离

```
内容（词库）   删了不影响已有进度记录，导出的 zip 里独立一块
进度（SRS）    card_state，按 sense.id 索引
```

用户想「只导出词库不要学习记录」时可选。**换设备恢复进度**是刚需。

### D. 备份

```
导出 .vwbak（zip）
  ├─ cards.json      词库内容
  ├─ progress.json   学习进度
  ├─ history.json    导入历史（什么时候导入了什么，可追溯可回滚）
  └─ manifest.json   版本号、导出时间、条数

自动快照：每次导入前存一份，保留最近 10 次
回滚：一键恢复到任意快照
```

### E. 备份之外的保险

```
导出文件不是唯一保障。自动快照存在本地，
另提供「导出到指定目录」，避开用户误删 App 数据的场景。
```

## 4. 数据组织

### 4.1 SQLite schema（内容与状态分离）

```sql
-- ============ 内容层（词库） ============

CREATE TABLE word (
  word       TEXT PRIMARY KEY,
  ipa        TEXT DEFAULT '',
  hidden     INTEGER DEFAULT 0,      -- 暂时不学
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE sense (
  id         TEXT PRIMARY KEY,       -- 内部 UUID，永不变
  word       TEXT NOT NULL,          -- FK → word.word
  slot       INTEGER NOT NULL,       -- 显示编号，可重排
  pos        TEXT DEFAULT '',
  gloss      TEXT NOT NULL,
  gloss_en   TEXT DEFAULT '',
  note       TEXT DEFAULT '',
  needs_refine INTEGER DEFAULT 0,    -- 骨架词标记
  deleted_at INTEGER,                -- 软删除，NULL=存活
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY(word) REFERENCES word(word)
);

CREATE INDEX ix_sense_word ON sense(word, slot);

CREATE TABLE sentence (
  id        INTEGER PRIMARY KEY,
  sense_id  TEXT NOT NULL,           -- FK → sense.id，不跟 slot
  idx       INTEGER NOT NULL,        -- 排序
  en        TEXT NOT NULL,
  zh        TEXT DEFAULT '',
  flagged   INTEGER DEFAULT 0,
  FOREIGN KEY(sense_id) REFERENCES sense(id)
);

CREATE INDEX ix_sent_sense ON sentence(sense_id, idx);

-- ============ 状态层（学习进度） ============
-- 全部挂在 sense.id 上，因此增删改序义项不影响进度

CREATE TABLE progress (
  sense_id     TEXT PRIMARY KEY,     -- FK → sense.id
  stability    REAL DEFAULT 0,
  difficulty   REAL DEFAULT 8.0,
  last_review  INTEGER,
  due_at       INTEGER DEFAULT 0,
  reps         INTEGER DEFAULT 0,
  wrong_n      INTEGER DEFAULT 0,
  pending_n    INTEGER DEFAULT 0,
  mastered     INTEGER DEFAULT 0,
  FOREIGN KEY(sense_id) REFERENCES sense(id)
);

CREATE INDEX ix_progress_due ON progress(mastered, due_at);

-- ============ 历史层 ============

CREATE TABLE import_log (
  id        INTEGER PRIMARY KEY,
  ts        INTEGER NOT NULL,
  word      TEXT NOT NULL,
  source    TEXT,                    -- 手动 / AI / 备份恢复
  summary   TEXT,                    -- "补例句 6 句，改释义 1 条"
  snapshot  TEXT                     -- 回滚用快照路径
);

CREATE TABLE review_log (             -- 现有结构，sense_id 改指 sense.id
  session_id TEXT NOT NULL, idx INTEGER NOT NULL,
  sense_id   TEXT NOT NULL,          -- 改指内部 UUID
  result TEXT NOT NULL, grade INTEGER NOT NULL,
  elapsed_ms INTEGER, ts INTEGER NOT NULL,
  PRIMARY KEY(session_id, idx)
);
```

### 4.2 为什么内容/状态/历史三层分开

```
内容改了   → 状态自动跟随（挂 sense.id）
状态清了   → 内容不动（想只重学一遍时用）
词库删了   → 状态保留（误删可还原）
导入回滚   → 只回滚内容，不动学习记录（不至于把背过的也退回去）
```

**每一层能独立操作，这就是「灵活」的存储基础。**

### 4.3 导入 JSON 协议

```json
{
  "format": "word.import",
  "schemaVersion": 2,
  "word": "crime",
  "senses": [{
    "slot": 1,
    "gloss": "犯罪，罪行（违法行为）",
    "glossEn": "(criminal law) an act punishable by law",
    "pos": "n.",
    "note": "关键：受法律惩罚",
    "sentences": [
      { "en": "He was convicted of a serious crime.", "zh": "他被判犯有严重罪行。" }
    ]
  }]
}
```

**设计点**
- `slot` 是**可选**的提示信息。用户写 `slot` 时按位置对位，没写时按 gloss 匹配
- 不用 `senseId` 字段——因为 ID 现在是内部 UUID，外部无法也不该关心
- 最小可用形式只需 `word` + `senses[].gloss`

### 4.4 导出协议

```json
{
  "format": "word.backup",
  "schemaVersion": 2,
  "exportedAt": "2026-10-16T12:00:00Z",
  "stats": { "words": 2998, "senses": 9200, "learned": 340 },
  "words":  [{ "word": "crime", "ipa": "...", "senses": [...] }],
  "progress": [{ "senseId": "a7f3...", "stability": 2.3, "reps": 7 }],
  "imports": [{ "ts": ..., "word": "crime", "summary": "补例句 6 句" }]
}
```

`schemaVersion` 递增，**旧字段永不删除**；未知字段被忽略而非报错。

## 5. 全库注入方式

| 来源 | 词数 | 义项策略 |
|---|---|---|
| 已精修 | 343 | 多义项已判准，保留全部 + 区分线索 |
| 待精修 | 2655 | **每词 1 条核心义**，标 `needs_refine` |

未精修的只给 1 条，理由：343 词实测「合并 45% / 舍弃 3%」，
说明自动细分义项的错误率很高。给一个能改的粗骨架，好过给一堆错拆的细卡片。
用户背到该词时补齐即可——**反正随时能改**。

## 7. 三个核心使用场景（逐条走查）

以下是实际会被走到的主要路径。每条都对应已定稿的表与 UI。

### 场景 1：遇到生词 → 搜索 → 看它有哪几个意思 → 增删改

**路径**

```
搜索框输入 "crime" → 命中 → 词条页（列出全部意思对）
                        ↓
              逐条判断：重复的删 / 已有的改 / 缺的补
                        ↓
              就地编辑，或用「复制模板」问 AI 补全
```

**搜索结果页**（先给词，再展开义项）

```
搜索 [crime________________]

crime  /kr��maɪm/  2 个意思  熟练度 ▓▓▓▓░
abandon                                        3 个意思  ▓░░░░

▼ crime
  ┌ s1 ── 已掌握 ▓▓▓▓▓ ──────── 12次 · 3天后 ─ [合并][⋯] ┐
  │ 犯罪，罪行（违法行为）                              │
  │ (criminal law) an act punishable by law...         │
  │ ▸ 备注  关键：受法律惩罚                            │
  │ ▸ 例句 2/5  [+复制提示] [+添加]                     │
  │    ① He was convicted of a serious crime.  犯罪    │
  │    ② ...                                           │
  └────────────────────────────────────────────────────┘
  ┌ s2 ── 学习中 ▓▓░░░ ──────────── 3次 · 明天 ─ [合并][⋯] ┐
  │ 罪恶（道德上的恶，不必然违法）                        │
  └────────────────────────────────────────────────────┘
  [+ 新增义项]   [导入 JSON]   [删除这个词]
```

**每个意思对自带三件事**：熟练度条、复习次数、下次复习时间。
因为熟练度是按意思对独立算的（见场景 3），所以这里必须逐条显示，
否则用户看到「crime 我会了」却不知道哪个意思还是生的。

**操作入口**

| 想做什么 | 怎么做 | 代价 |
|---|---|---|
| 删掉重复的意思 | 义项卡 `[⋯]` → 删除（软删除） | 一键 |
| 改已有释义 | 点 gloss 文字直接改 | 就地，不跳页 |
| 补充缺失的意思 | `+ 新增义项` | 一键 |
| 合并两个意思 | 任一义项卡 `[合并]` | 一键 |
| 拆分一个意思 | `[⋯]` → 拆分为两条 | 句子让用户选归属 |
| 调整顺序 | 拖拽 | — |
| 批量删 | 搜索结果页勾选 → 批量操作 | — |

**「合并」放在每张义项卡上**，因为合并是高频操作，不该藏进二级菜单。
合并时两边的复习记录相加，熟练度取较高值——改结构不该毁掉已有积累。

### 场景 2：点进某个含义 → 看例句和翻译 → 增删改 → 导出问 AI → 导入覆盖

**例句区（在义项卡内部，展开即见）**

```
例句 2/5                                          [+复制提示] [+添加]
  ① He was convicted of a serious crime.
     他被判犯有严重罪行。                                [⭐标记] [删]
  ② The police are still investigating the crime.
     警方仍在调查这起犯罪。                               [⭐标记] [删]
  + 添加例句
```

- 行内编辑，点文字即改，失焦才校验
- `⭐标记` =「这句有问题」，事后集中修（复用现有 sentence_flag 表）
- `2/5` 计数一眼看出缺什么

**「复制提示」→ 问 AI**

复制到剪贴板的内容：

```
单词: crime
释义: 犯罪，罪行（违法行为）
英文释义: (criminal law) an act punishable by law; usually considered an evil act
备注: 关键：受法律惩罚

请核验并补全：
1. 上述中文释义是否准确？不准确请给出更好的。
2. 为该义项造 5 个英文例句 + 中文翻译，每句必须能体现
   该义项的独特用法（能与同词其他义项区分开）。
3. 按下列 JSON 输出，不要有任何其他文字：

{"word":"crime","senses":[{"slot":1,
  "gloss":"...","sentences":[{"en":"...","zh":"..."}]}]}
```

**「导入 JSON」→ 逐条对比**

粘贴后进入对比屏，**每个冲突单独决策**：

```
导入 crime —— 本地 2 句 / 导入 5 句

例句
  本地  ① ... ② ...
  导入  ① ... ② ... ③ ... ④ ... ⑤ ...

  [追加缺的 3 句]   [只保留本地 2 句]   [用导入的 5 句]

中文释义
  本地: 犯罪，罪行（违法行为）
  导入: 犯罪，罪行
        [保留本地]  [用导入的]

本地有、导入没有的义项
  s3 窝藏（庇护罪犯）           [保留]

导入有、本地没有的义项
  s4 包庇                     [采纳]  [丢弃]

              [取消]        [确认导入]
```

**默认动作：保留本地**（用户可能自己改过）。
**不提供「全部用导入的」批量覆盖**——批量覆盖是丢数据的开始。

导入前自动快照，可回滚（见 §2.D）。

### 场景 3：熟练度按意思对独立计算

**这是「单词-含义对为核心」的必然结果。**

```
crime s1「犯罪/罪行」   复习 12 次  stability 2.3  已掌握  下次 3 天后
crime s2「罪恶」       复习  3 次  stability 0.8  学习中  下次 明天
```

同一个词的两个意思，是**两条独立的记忆曲线**。因为它们的例句、用法、
难度完全不同——「罪恶」的例句不该混进「犯罪」的曲线里。

**复习计划与记忆曲线**（FSRS 口径）因此按 `sense.id` 索引：

```sql
CREATE TABLE progress (
  sense_id   TEXT PRIMARY KEY,   -- 挂义项内部 UUID
  stability  REAL,               -- 记忆强度 → 决定下次间隔
  difficulty REAL,
  due_at     INTEGER,            -- 下次复习时间
  reps INTEGER, wrong_n INTEGER, mastered INTEGER,
  ...
);
CREATE INDEX ix_progress_due ON progress(mastered, due_at);
```

出题时按 `due_at` 取到期义项；同一��的两个意思可能一个到期一个没到期，
**这正是我们要的**——它们本来就不是同一件事。

**为什么必须用内部 UUID 而不是 s1/s2**

这是本设计里最容易被省掉、但一省就出错的点：

| 用户操作 | 用 s1/s2 当主键 | 用内部 UUID |
|---|---|---|
| 在 s1 前插入新义项 | s1→s2，后面全部漂移，**进度错位** | 进度自动跟着义项走 |
| 删掉 s2 | s3→s2，**s3 的进度挂到 s2 头上** | 存活义项完全不受影响 |
| 调整顺序 | 全部错位 | 全部跟着走 |
| 合并 s2+s3 | 只能留一个，另一个的进度丢失 | 两边相加，取较高 |

用户**感知不到前两种错位**：进度条数值还在，但对应的含义变了。
所以这不是「优化」，是正确性问题。

## 8. 导航结构（修正：首页不是词库列表）

前一版把「词库列表」当首页，是错的。首页应该是**学习入口**，不是数据库浏览。

### 8.1 三级页面结构

```
首页（干净）
  │ 一个随机单词 + 它的例句 + 搜索框
  │ 搜索 / 点例句里的词
  ↓
单词页（列出全部意思）
  │ crime · 2 个意思
  │  s1 犯罪，罪行      ← 点进去
  │  s2 罪恶
  ↓
意思页（一个意思 = 一张卡）
  │ 释义 + 例句列表 + 编辑 + 复制模板 + 导入
```

**为什么是三层**：`词 → 意思 → 意思` 是内容的真实结构。
把它们压成两层（搜索结果直接列例句）在 `crime` 这种多义词上会挤成一坨。

### 8.2 首页：只做三件事

```
┌─────────────────────────────┐
│  🔍 搜索单词____________     │  ← 搜索框在顶部
├─────────────────────────────┤
│                             │
│        abandon              │  ← 随机一个词（可跳过）
│        /əˈbændən/  vt.      │
│                             │
│   放弃，抛弃                 │  ← 随机一个意思
│                             │
│  ① They had to abandon...   │  ← 它的例句
│     他们不得不弃车。          │
│  ② She abandoned her plans. │
│     她放弃了计划。            │
│  ③ ...                      │
│                             │
│  [跳过]      [练这个词]      │
└─────────────────────────────┘
```

**不放**进度条、不放统计、不放「缺例句的词」列表。
那些是看板和词表的事，首页不该背。

**三个动作**
- 搜索框 → 单词页
- 点例句里的任意词 → 该词的单词页（顺藤摸瓜）
- 跳过 → 换下一个；练这个词 → 进训练

### 8.3 单词页

```
┌─────────────────────────────┐
│  ← crime            复制模板 │
├─────────────────────────────┤
│  /kraɪm/   n.               │
│                             │
│  s1 犯罪，罪行（违法行为）  ▓▓▓▓▓ │
│     已掌握 · 12次            │  ← 点进去
│                             │
│  s2 罪恶（道德上的恶）      ▓▓░░░ │
│     学习中 · 3次             │
├─────────────────────────────┤
│  [+ 新增意思]   [导入JSON]   │
└─────────────────────────────┘
```

这里是**导航**，不是编辑界面。编辑在下一层。

### 8.4 意思页：编辑都在这

```
┌─────────────────────────────┐
│  ← crime · s1        ⋯        │
├─────────────────────────────┤
│  犯罪，罪行（违法行为）        │  ← 点字即改
│  (criminal law) an act...     │  ← 点字即改
│                             │
│  ▸ 备注  关键：受法律惩罚      │
│  [合并] [拆分] [删除]         │
├─────────────────────────────┤
│  例句 2/5                    │
│  ① He was convicted...   ⋯   │
│     他被判犯有严重罪行。       │
│  ② The police are...     ⋯   │
│  ③ + 添加                    │
├─────────────────────────────┤
│  [复制给AI]   [导入JSON]      │
└─────────────────────────────┘
```

### 8.5 底部导航（4 个）

```
┌─────────────────────────────┐
│  🏠首页  📚词库  🎯训练  ⚙️更多 │
└─────────────────────────────┘
```

「词库」= 可搜索、可筛选的列表（搜索框在这里也能用，不只首页）
「更多」= 看板 / 记录 / 备份 / 设置

**搜索放两处**：首页顶部（快速查）+ 词库页（筛选列表）。
备份、记录这类低频功能收进「更多」，不占 tab。

### 8.6 响应式

| 断点 | 布局 |
|---|---|
| 移动 (<768) | 单列，上文即最终形态 |
| 平板/桌面 (≥768) | **两栏**：左列表右详情。<br>点意思 → 右栏直接显示该意思的例句，<br>不跳页。词库页可三栏（词 / 意思 / 例句）。 |

大屏的价值就是**省掉来回跳转**，不是把字放大。

### 8.7 数据导航路径

```
首页随机词 ──→ 单词页 ──→ 意思页
   │              ↑         │
   └── 搜索 ──────┘         │
                          导入JSON / 复制模板
```

对应接口（供实现参考）
```
GET  /home            随机一个词 + 一个意思 + 3 句
GET  /word/:w         该词全部意思 + 各自熟练度
GET  /sense/:id       单个意思的释义 + 全部例句
PUT  /sense/:id       编辑释义/备注
POST /sense/:id/sents 增删例句
POST /sense/:id/merge 合并义项
GET  /search?q=       搜索
POST /import          导入 JSON → 返回 diff 供逐条决策
POST /import/apply    应用已确认的 diff
GET  /backup/export   导出
```

## 9. 修正记录

前一版（§3.3）把词库列表当首页，把编辑直接摊在列表里。问题：

```
┌─────────────────────────────────────────┐

├─────────────────────────────────────────┤
│                                         │
│   abandon                    [朗读]     │  ← wordBadge，可点发音
│   vt. /əˈbændən/ T2 TRAP·熟词僻义        │  ← tagLine
│                                         │
│   They had to a·band·on the car.        │  ← 目标词 <mark> 高亮
│                                         │
│   想清楚这个词在这里的意思               │  ← hint
│   ┌─────────────────────────────────┐   │
│   │  — 点击空白处显示选项 —           │   │  ← blankBox
│   └─────────────────────────────────┘   │

│                                         │

└─────────────────────────────────────────┘

答后：
   explain 区展开
   ├─ 正确答案 + 中文释义
```

### 10.2 现有设计里值得保留的四个判断

| 做法 | 为什么对 |
|---|---|
| **目标词 `<mark>` 高亮** | 句子里的第二次指示才告诉眼睛「看这里」。顶部徽章虽然也显示词，但不够 |
| **答案区才显示 glossEn** | 训练时露英文释义等于泄题 |
| **句子标记（flag）** | 背的时候发现问题随手标，标了这句不再出现，事后集中修。这是内容质量的闭环 |
| **「我不会」放在选项之前** | 先给台阶，再给选择，减少挫败 |

**这四点我原方案里全都没有。原方案是「训练页保持现状」，但没想过它跟新内容模型怎么接。**

### 10.3 v2 需要改的地方
