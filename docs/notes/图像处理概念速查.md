## 1. 颜色聚类（k-means）

**一句话**：图里颜色种类很少，先把「有哪些颜色」找出来，然后按颜色给像素贴标签，
而不是去猜「哪些像素算亮、哪些算暗」。

### 为什么需要它

你之前用**灰度阈值**提取线条，遇到的现象是：

> 阈值调高 → 线断了；阈值调低 → 什么物体都成了线。

这不是参数没调好，是**判据选错了**。原因：

- 组态图里的线是**彩色**的（青、绿、橙……），亮度可能和背景接近。
- 抗锯齿让线的边缘有一堆过渡色，亮度是**渐变**的，没有一个干净的「阈值」能切开。
- 背景可能有网格、阴影、渐变，本身就不是纯色。

**灰度阈值在问**：「这个像素够不够亮？」
**颜色聚类在问**：「这个像素属于哪一族颜色？」

后者对组态图这种**少色类**图像稳定得多 —— 通常整张图只有 5~15 种主色，
线就是其中某一两族。

### 怎么用（概念）

```python
img = cv2.imread('scada.png')
Z = img.reshape(-1, 3).astype(np.float32)      # 所有像素拉平成一维
K = 8                                         # 猜 8 种主色
criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 10, 1)
ret, label, center = cv2.kmeans(Z, K, None, criteria, 3, cv2.KMEANS_PP_CENTERS)
label = label.reshape(img.shape[:2])          # 每个像素现在是 0~7 的编号
```

拿到 `label` 之后你就有了**一张分割图**：每个像素说「你属于第 3 号颜色」。
下一步是人工看一眼哪几个编号是「线」、哪几个是「文字」—— 通常 5 分钟就能标出来。

**技巧**：K 不要瞎猜。先取 16，拿到 16 个中心色，人眼一看就知道有几个是真的，
再合并相近的。组态图通常 6~10 个。

**坑**：抗锯齿边缘会产生「过渡像素」，它们可能被归到第三类。处理办法是先做一次
轻微的形态学闭运算把线加粗一点，或者忽略那些只在边缘出现的簇。

## 2. 形态学：膨胀 / 腐蚀 / 开 / 闭

**一句话**：用一个小「笔刷」在图上滑动，按规则修改像素。用来修整形状。

| 操作 | 做什么 | 什么时候用 |
|---|---|---|
| **膨胀** | 亮的区域往外长一格 | 把断了的线接上、把细线加粗 |
| **腐蚀** | 亮的区域往里缩一格 | 去掉细小的噪点毛刺 |
| **开运算** = 先腐蚀后膨胀 | 去掉孤立小点，保留大块 | 清噪点 |
| **闭运算** = 先膨胀后腐蚀 | 填上小空洞，连上断裂 | 补线 |

**为什么线会断**：线是 1~2 像素宽，中间被 JPEG 压缩或抗锯齿打散成几段。
闭运算能把几像素内的缺口补上。

**注意**：形态学会改变形状。用的笔刷（核）越大，变形越厉害。
线宽只有 1~2px 时，核必须很小，否则线会变粗、粘连在一起。

## 3. 骨架化（Zhang-Suen / morphological thinning）

**一句话**：把一条粗细不一的线，压成**中心线上 1 像素宽**的线，形状不变。

### 为什么需要它

组态图的连线有的地方 3px 宽、有的地方 1px。你想「沿着线走」，
但线条宽度不一致就没法走。骨架化之后，**每一根线都是单像素宽**，
下一步追踪就变成「从一个像素出发，往没走过的邻居走」。

### 怎么做（概念）

反复做两件事，直到收敛：
1. 找出所有「有 8 个邻居、其中恰好 1 个前景邻居」或「2 个且它们不相邻」的像素，标记为待删；
2. 同时删掉这些像素（注意是**同时删**，不是边算边删）。

这会像削苹果一样，一层层把边缘削掉，最后剩下的就是中心线。

OpenCV 里没有直接的骨架化，要用 `skimage.morphology.skeletonize`。

### 骨架化之后就是「追踪」

有了单像素宽的线，把它们串成折线：
- 从一个端点（只有 1 个邻居的像素）出发
- 走到没有未访问邻居为止
- 记录走过的路径 → 得到一条折线
- 重复直到没有端点

**难点是交叉点**：两条线交叉处，中心的像素有 4 个邻居，分不清该往哪走。
**不要猜** —— 到分叉处就停下来，标记为「需要人工判断」。
你之前失败的原因之一就是「所有分叉都得猜」，那必然出错。

## 4. 矢量化（Vectorization）

**一句话**：把位图里的形状变成「坐标点序列」，也就是从「一堆像素」变成
「一条带端点的线 + 一组控制点」。

**矢量化 ≠ 轮廓提取**。轮廓提取（contour）拿到的是边界，
而一根线**没有内部**，它的轮廓就是它自己（1px 宽的线，轮廓和骨架重合）。

组态图的场景下，实际做法是：
```
颜色聚类 → 二值化 → 闭运算补断点 → 骨架化 → 追踪成折线 → 相邻折线合并
```
最后得到的是一组「折线」，也就是可以直接转成 SVG `<path d="M..L..">` 的东西。

这才是「图 → JSON」里**几何部分**该走的路。

## 5. 模板匹配（Template Matching）

**一句话**：拿一张已知的小图（模板），在整张图里滑动，找最像的那个位置。

### 为什么它比「让模型认」靠谱

- **给出精确坐标**（像素级），因为它就是在比像素
- 结果**可复现**：同样的输入永远给同样的输出
- 可以离线跑，**不依赖任何大模型**

### 用法（概念）

```python
res = cv2.matchTemplate(big_img, template, cv2.TM_CCOEFF_NORMED)
min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(res)
x, y = max_loc          # 模板左上角在大图里的位置
w, h = template.shape[::-1]
box = (x, y, x+w, y+h)  # 这就是组件的精确外框
```

### 前提：闭集

模板匹配的前提是**你知道要找什么**。所以第一步不是写代码，是：

> 跟甲方要一份组件清单：有哪些泵、阀门、容器、仪表，各自长什么样。

如果拿不到（你现在的处境），那就**人工看图整理一份**。这份清单本身是
**业务映射表**（甲方组件 → 乙方组件），人工搭也得做，只是没人愿意先认它。
做完它之后，剩下的识别工作才有可能自动化。

### 注意

- 模板要和原图**同缩放比例**，不同比例要用多尺度金字塔（scale pyramid）
- 甲方如果有多个主题/皮肤，每个主题要一套模板
- 线条粗细可能因版本而异 → 对模板做一点形变容错，或者用边缘图（不填色）来匹配

## 6. 感知哈希 / SSIM（用来判「还原得像不像」）

**一句话**：给两张图算一个数字，0~1 之间，越接近越像。用来**自动判断结果好坏**。

这是**整个方案里最关键但最容易被忽略的一环**，因为它提供了「对」的客观标准。

### 怎么用

流程是这样的：

```
甲方图 ──→ 生成 JSON ──→ 渲染成图 ──→ 与甲方图比较 ──→ 分数
                ↑                                    │
                └────────── 分数差就改 ────────────────┘
```

有了这个分数，你能：
- 自动**拒绝垃圾样本**（分数低于阈值就不入库）
- 量化「这次比上次好了多少」
- 决定「还差多少才够交付」—— 有个数字就能跟甲方谈验收标准

SSIM（结构相似度）在 OpenCV 里：
```python
score = cv2.quality.QualitySSIM_compute(ref, dst)
```
感知哈希（更粗，但对整体布局变化敏感）：
```python
import imagehash
h1, h2 = imagehash.phash(img1), imagehash.phash(img2)
dist = h1 - h2        # 0 = 几乎一样
```

### 为什么这条最重要

你之前两次尝试（视觉模型、图像算法）共同的缺失是：
**没有一个客观的「对不对」的标准**，所以改了一版也不知道有没有变好，
只能凭感觉。有了闭环分数，这件事才从「手艺」变成「工程」。

## 7. 视觉模型（VLM）在这件事里该干什么

**该做的**：
- 「这个形状是离心泵还是齿轮泵」
- 「这段文字是设备位号还是数值」
- 「哪些连接线的走向有歧义，需要人确认」
- 对疑难区域做仲裁

**不该做的**：
- ❌ 输出精确坐标（原理上做不到，见 [组态图转JSON.md](./组态图转JSON.md)）
- ❌ 判断「这里有没有一条线」（漏检和误检都不可控）

**分工原则**：**几何测量交给算法，语义理解交给模型。**
