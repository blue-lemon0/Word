## 踩坑记录为什么单独一份

这一份记的是**「不报错但结果不对」的坑**。写错代码会报错，
改错代码不会——控制台干净、构建成功、测试全绿，而结果就是不对。
这类问题只能靠「知道有这个坑」来省时间，所以每条都重点写**判据**
（下次怎么在 30 秒内认出它）。

其中能机械判定的部分，已经写成断言挂在 `scripts/verify_docs.py` 的
「真机交互守卫」里（当前 145 项），跑一次 `python scripts/verify_docs.py` 就会拦。
数字由脚本自己核对：文档写错一项，这一轮就直接 FAIL。

## 为什么其他东西放这里

组态图那个方向短期用不上，但它有两个特点适合攒着：

1. **甲方拿不到原始文件**这类约束很常见，不止组态图。
2. 之前两次尝试的**失败原因**比成功经验更值钱 —— 换个行业也会遇到
   「让视觉模型给坐标」「阈值调参调不出来」这类坑。

写下来的目的不是「将来一定做」，而是**下次遇到同类问题时能想起来**
「哦，这个坑我踩过，路在另一条」。
