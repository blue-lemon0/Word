# 组态图截图 → 可渲染 JSON：问题分析与路线

> **状态：暂缓。** 想法和坑先记在这，等当前产品打磨完再动手。
> 背景：甲方只给组态图的**截图**，不给文件；两边组态软件的组件不一样，
> 人工重搭太耗时。想用视觉模型/图像算法自动转成 JSON。

---

## 一、先说结论

**两次失败都不是「调参不够」的问题，是工具选错了层级。**

- 让视觉大模型输出像素坐标 —— 原理上就不该指望
- 用灰度阈值提取线条 —— 判据本身不稳定，换任何参数都救不回来

可行的路线是：**几何测量交给传统算法，语义理解交给模型，
再用一个可验证的闭环来迭代。**

---

## 二、为什么视觉模型给不出坐标（即使加了标尺）

### 2.1 它不是在「测量」，是在「生成」

视觉大模型（VLM）的工作方式：图像 → 视觉 token → 自回归输出文本。

它**没有像素缓冲**，不能「打开图片量一下」。它输出的坐标是**基于先验生成**的，
像是在说「这种界面，泵一般在中上部偏左」—— 而不是真的看到了某个像素在哪。

**所以加标尺提高的是「你的可读性」，不是它的能力。** 这是当时最大的误判：
以为标尺能帮模型测量，其实模型根本没在测量。

### 2.2 量化天花板

模型通常输出 0~1000 的归一化坐标。对一张 4000×3000 的图：

- 1 个单位 = 4 物理像素（这已经是最乐观的情况）
- 实际误差是**百分比级**，不是量化级

也就是说，就算模型完美理解了布局，坐标精度也**天然达不到像素级**。
而重搭组态图需要像素级 —— 一个框偏 10 像素，连线就接不上了。

### 2.3 连接拓扑是另一个难度层级

「泵 A 的出口连到阀门 B 的入口」—— 这需要追踪一根细的、低对比度的、
可能带虚线的曲线跨越整张图。

人类看到的是**整体关系**（图 Gestalt），模型看到的是**纹理**。
细长结构上的空间连续性是 VLM 的弱项，加训练也难补上，因为它是
「结构推理」而不是「识别」。

### 2.4 组件没有稳定锚点

每家组态软件画泵、阀、容器的方式都不一样（形状、颜色、符号标准都不同）。
模型没有可对齐的模板，只能靠「看起来像不像」的先验，于是位置和类别都不稳。

### 2.5 点位坐标是最小文字

PLC 点位那几个小数字在原图里可能只有 8~10 像素高。VLM 对图中细字本来就弱，
再叠加「把数字绑到具体针脚上」的空间绑定，难度翻倍。

## 三、为什么图像算法那次也失败

**现象**：一条线断成几十段；阈值调高就识别不出，调低就什么都是线。

**根因**：判据选错了 —— 用**灰度**判断「是不是线」，而这条线在
「颜色」上区分度很高，在「亮度」上可能和背景差不多。加上抗锯齿让
边缘亮度渐变，所以根本不存在一个干净的灰度阈值。

你当时的直觉「这条线断断续续」也说明线是能看见的，只是提取策略不对。

**正确做法**：见 [图像处理概念速查.md](./图像处理概念速查.md) 第 1 节。
一句话：**别在灰度上做阈值，在颜色上做分类。**

## 四、可行的路线

### 阶段 1：把「闭集」搞清楚（业务活，不是技术活）

> **甲方组件清单拿不到 → 只能人工看图自己维护。** 这是现实，
> 但要清楚它是什么：它不是「AI 的障碍」，它本身就是**必要交付物**。

因为两边组件不一样，所以**甲方组件 → 乙方组件的映射表是必做的**。
人工重搭也要做这张表，只是没人愿意先认领它。

清单最少要有这几列：

| 列 | 用途 |
|---|---|
| 甲方组件名 | 识别出来后回查 |
| 甲方组件的样子（截图/编号） | 做模板匹配用 |
| 乙方对应组件 | 输出的目标 |
| 缩放比例 / 主题 | 模板要做几套 |
| 常见数量 | 校验识别结果对不对 |

**3~5 张代表性图**应该能拿到（你说得对，20 张不现实）。
关键是要覆盖**不同的组件密度和连线复杂度**，而不只是数量。

### 阶段 2：先上纯几何，完全不用模型

管线见 [图像处理概念速查.md](./图像处理概念速查.md)：

```
颜色聚类 → 分类人工标一下 → 闭运算补断 → 骨架化 → 追踪成折线 → 合并
```

组件用**模板匹配**定位（精确、可复现、离线）。

交叉点**不猜**，标记为 ambiguous 等人确认。

**先看纯几何能到多少分** —— 这一步能验证「数据本身够不够清晰」。
如果甲方图是低分辨率截图压缩过的，那可能连这一步都过不去，早知道早好。

### 阶段 3：建立闭环分数（★ 最关键，别跳过）

```
甲方图 ──→ JSON ──→ 渲染成图 ──→ 跟甲方图比 ──→ 分数
              ↑                          │
              └──────── 分数不够就改 ─────┘
```

用 SSIM 或感知哈希算分。有了这个：
- 能自动筛掉垃圾样本
- 能量化进步
- **能把「改好了没」从感觉变成数字**

这是你前两次尝试都缺的东西。没有它，就是在黑暗里改代码。

### 阶段 4：VLM 只做分类和仲裁

几何部分做完之后，剩下「这个是泵还是阀」「这几个数字哪个是位号」
这类语义判断，交给 VLM。它在这一层是**可靠且高效**的。

**不要让 VLM 碰坐标。**

## 五、想不清楚的地方（下次做的时候先解决）

- [ ] 「渲染成图」这一步用什么？
      是用浏览器渲染 SVG，还是找到乙方组态软件的导出/预览接口？
      如果只有截图能导出，那闭环分数怎么算？
- [ ] 甲方图的**分辨率和压缩质量**？如果是低质 JPEG 截图，
      颜色聚类可能因为压缩伪影而不稳
- [ ] 连线的**语义**怎么表达？只画线不够，还要知道
      「这根线是给水还是回水」—— 这是甲方知识，只能问人
- [ ] 点位数字和针脚的空间绑定，纯几何做不了，可能必须靠 VLM + 人工校对
- [ ] 三~五张代表性图的**挑选标准**该定成什么？
      建议：至少一张「密集连线」、一张「稀疏」、一张「带表格/文字区」
