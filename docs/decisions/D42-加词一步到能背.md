# D42 —— 加一个词，目标是「一步到能背」

> 决策日期：2026-10-19
> 一句话：**加词的动机是「刚遇到它、想马上能背它」，不是「先建个空壳，回头再写」。**

---

## 一、旧流程把内容生产转交给了用户

```
输入 nuance → 建词条 + 空义项 → 跳到编辑页 → （用户自己写释义、自己造句）
```

中间那一步「等你自己写」是断裂点：空义项进不了出题池（没有例句），
所以「加进来了」和「能背了」之间隔着一整段内容工作。
而大多数人加词的时机是**正在读/正在练、刚被某个词卡住**——那时没人想写释义。

## 二、新流程：三条路，按「能不能立刻用」排序

| 情况 | 走哪条 | 结果 |
|---|---|---|
| 配了 AI | 「AI 生成义项和例句」→ 提议浮层 → 点应用 | 直接得到 1-3 个义项 + 每义项 1-2 句例句 |
| 没配 AI | 「只建词条，自己写」 | 词条 + 占位义项（`needsRefine`），进编辑页 |
| 已经在库里 | 「去这个词」 | 不重复建，直接跳过去 |

三条路都指向同一个终点：**一个能背的卡**（或明确知道差什么）。

## 三、还是那条边界：AI 只提议

「AI 生成义项和例句」这个按钮同意的是「让 AI 先生成」，
不是「替我决定内容」——生成结果进的是**提议浮层**（和词条页、体检页同一张），
逐条看完点应用才落库。落库前自动存内容快照。

## 四、输入框的细节

- **失焦/输入时查一次重**：已经在库里就当场说出来，并给「去这个词」——
  而不是让人点了「加进词库」才收到一句「已经在库」的报错。
- 音标可留空，但填了会用（`addWord` 会去掉两边斜杠）。
- 回车键 = 主行动（配了 AI 就是「生成」，否则是「加进词库」）。

## 五、判据

| 断言 | 拦的是什么 |
|---|---|
| 加词能一步生成义项与例句，且走提议浮层 | 直接写库（绕开人的确认） |
| 已在库的词不重复建，给「去这个词」 | 建出第二张空壳 |
| `fillWord` 只用于空壳 | 对已有释义的词做「生成」，等于重写别人的内容（D40 的规则） |

真机：输入一个库里没有的词 → AI 生成 → 浮层里看到义项与例句 → 应用 → 进词条页。
