# D27 · 首词规则的例外：口语引申义挂在别的词下

日期：2026-10
状态：**已生效（`_wordnet_exceptions`）。** 现有数据一字未动。

## 问题

D20 定的 `first_word_only` 是硬规则：只收以该词为首词的 synset。
理由是 `wn.synsets("reply")` 会返回 `answer.n.01`（「答案」的义项）——
把同义词的意思算到本词头上。

但这条规则会漏掉一类真实义项：**英语口语的引申义，往往挂在另一个词的 synset 下**。

```
arrest  vi. 拘捕、阻止
       → collar.v.01  put a collar on; arrest
         （首词是 collar，因为逮捕要给犯人上颈圈）

bomb    vi. 失败
       → turkey.n.05 an event that fails badly
         （首词是 turkey，"像火鸡一样失败"）
```

中文词典忠实记录了这些义项，英文侧只是把它挂在借喻的源词上。
`first_word_only` 拦掉它们 = 丢真义项。

## 关键证据：全库扫下来，这种碰撞是 0

对全库未处理词做「英文释义 vs 全部现有中文义项」的零重合扫描，
剩余未处理词为 **0**。也就是说 `arrest`/`bomb` 是**罕见**，不是普遍。

既然罕见，就不该为一个罕见机制去改动 `first_word_only`（那会让 `reply`→`answer`
这类噪声大规模回来）。正确做法是留一个**窄口**：人工逐词指定。

## 机制

decisions 里加一个可选键：

```json
"_wordnet_exceptions": ["bombard.v.02", "turkey.n.05"]
```

用 **synset 名**（不是序号，避免版本漂移）指定要强制收入的 synset。
这些 synset **绕过全部自动过滤**：

```
lexname 黑名单 / drop_patterns / usage_domains / min_en_words
```

理由：既然人工指定了，就不该再被自动规则否决——那会造成
「decisions 声明了但产出没有」，比直接报错更难查。

`fromLines` 照常用 `[["wn", "synset.name"]]` 引用，traceable。

## 已用到的词

```
arrest  collar.v.01 / check.v.18     逮捕、阻止
bomb    bombard.v.02 / turkey.n.05   轰炸、(引申)彻底失败
```

## 两个实现坑

**① 例外键名曾写成 `_wordnetExceptions`**（驼峰），
而 `exceptions_for()` 读的是 `_wordnet_exceptions`（下划线）。
结果 `exceptions_for("bomb")` 返回 `[]`，例外的 synset 正常地被过滤掉，
`fromLines` 引用失败但**报错信息指向"已被清洗掉的英文行"**，不指向键名。
改对键名后立刻恢复。教训：**读取失败要与写入失败区分开**。

**② 例外必须绕过过滤，而不是"降低过滤标准"。**
否则 `bombard.v.02`（动词、短释义）会卡在 `min_en_words=3` 上，
让人以为机制没生效。

## 一个更普遍的观察

这类「借喻挂载」在英语里都是**固定搭配**：

```
go over like a bomb        彻底失败
put someone in prison      入狱
take into custody          逮捕
```

它们本身是地道用法，只是**不产生活跃的单词义位**。
所以产出里保留它们是对的（中文词典就是这么教的），
但造句时必须用固定搭配作线索，否则会造出语法正确但不地道的句子。
`note` 字段里标了这一点。
