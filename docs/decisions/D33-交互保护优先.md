# D33 · 交互保护优先：例句要显式进编辑态，确认走应用自己的弹层

日期：2026-10-18
状态：**已生效**，真机逐项验证过。

## 起因

一次真机使用反馈里，用户连着提了五个问题：

1. 义项页写着「id 永不随排序变……」，除了占地方对用户没啥用；
2. 义项页左上角返回会**死循环**：义项页 → 单词页 → 返回 → 又回义项页；
3. 例句**点一下就改**，容易误删误改；
4. 键盘避让**避过头**，页面窜到最顶、内容被推出屏幕；
5. 训练页结算「回首页」跳到**空白页**。

前三个和第 4 条都不是「做错了」，是**原来的默认做法本身就错了**。
这一篇记的是这几个决定，以及为什么这么定。

## 决定

### 1. 例句必须显式进编辑态（与释义相反）

释义、英文释义、备注保持「点字即改，失焦落库」。
**例句不行**：每行加「改 / 改好了」，`contenteditable` 与 `wb-edit`
都只在编辑态挂上。

理由是**代价不对称**：释义写错了一眼看得见，例句错了要等下次复习才发现。
而例句是背单词的核心内容，一句被手抖改坏，用户当天无感、几天后才发现学的是错的。

补充两条配套：

- 进入编辑态时**光标放到句末**（`focus()` 默认落在开头），
  否则接着打字会插到句子最前面；
- 编辑时**整行**（含译文和「改好了」按钮）都要留在键盘上方，
  所以键盘避让需要一个「避让对象可以比聚焦元素大」的机制
  （`keyboard.ts` 的 `setAvoidTarget`）。

删除例句是**硬删**（不进回收站），所以删除也加了确认。

### 2. 确认弹层全部走应用自己的底部 Sheet

**全站不再有原生 `confirm()` / `prompt()`**，统一用
`src/components/ConfirmSheet.vue`。

真机截图里的原生对话框是这样的：

```
The page at "https://appassets.androidplatform.net" s…
删掉这句？
CANCEL              OK
```

标题那行 URL 是 Chromium 加的、按钮文字由系统语言决定、正文挤成一段，
和这个 app 没有任何关系 —— 而这恰恰是最需要用户停下来看一眼的地方。
换成自己的底部弹层之后：中文按钮、正文 `\n` 真的换行、
破坏性操作用红色按钮；需要填字的（拆分义项填新释义）用同一个组件的 `input` 模式，
把 `prompt()` 也收了进来。

守卫：`scripts/verify_docs.py` 里有「全站没有原生 confirm()/prompt()」一条。

### 3. 顶栏返回 = 系统返回键 + 兜底落点

两页各写各的返回时，「意思页 push 回单词页」和「单词页 back 回意思页」
正好对着来，围成一个环。现在统一走 `src/nav.ts` 的 `goBack(router, parent)`：

```ts
if (window.history.length > 1 && from !== cur) router.back()   // 等价于系统返回
else router.replace(parent)                                    // 兜底
```

两种不能 `back()` 的情况：

- **没有上一层**（书签/桌面图标进来的深链）：`back()` 是空操作，
  表现为「按了没反应」；
- **上一层就是自己**（合并/删除义项后 `replace` 回同一页，
  历史里留下两条一模一样的单词页）：不处理就是「退到一模一样的地方」。

另外**合并/删除之后必须 `replace`**：那个义项已经不存在了，
再往回退只会退到「找不到这个意思」的页面。

守卫：「顶栏返回统一走 goBack（不含裸 `router.back()`）」。

### 4. 首帧就要有内容，骨架屏只是兜底

义项页原来是 `<div v-if="sense">…</div> <div v-else>「找不到这个意思」</div>`。
读库要几十毫秒，这段时间渲染的是**「找不到」** —— 一句假话。
用户报的现象是「点进去一瞬间闪一下别的界面，看不清」，
逐帧采样量到闪了 **37ms**。

把「找不到」换成骨架屏之后，**用户仍然报闪**。CDP screencast 抓到了那一帧：
只剩一张灰条卡片，标题栏都是空的（9 KB vs 稳定帧 29 KB）。

结论是：**跳转的时序是 mount → 渲染第一帧 → await 读库 → 第二帧，
第一帧不管渲染什么都是一次可见的跳变。** 骨架屏只是把「说假话」
换成了「页面空一下再突然长出来」。

真正的解法是**首帧就用内存里已有的数据渲染**：

- `db.ts` 的缓存同时留着 promise 和解析后的值，新增 `cachedNow()` 供首帧同步读；
- 单词页/意思页首帧同步读，读不到才退化成骨架屏；
- 「哪张表热了」不能靠碰巧 —— 同一段跳转代码，从词库进来闪、从单词页进来不闪，
  取决于用户之前去过哪儿。所以启动时 `void warmTables()` 统一预热
  （真机四张表约 15ms，不 await，不阻塞首屏）；
- 次要信息（例句条数）没算出来之前**不写「0 句」** ——
  「假数 → 真数」又是一次跳变。

验证：词库→单词页、单词页→义项页、义项页→返回、冷启动→单词页，
四种切换的 screencast 都是**一帧直达完整界面**，中间帧消失。

### 5. 只挪被挡住的那一点

键盘避让原来把元素**顶部**当基准，输入框只被盖住 43px 也能让页面跳 450px，
再被 `Math.max(0, …)` 悄悄吃掉向上那一截 → 「窜到最顶、内容出屏」。

改成：算差多少 → 夹到合法滚动区间（键盘弹出后 `.wb-page` 的
`padding-bottom` 加了 `--kb`，文档变高了，不夹会越滚到文档底之外）→ 滚那一点。
全可见时**一个像素都不动**。

### 6. 顺手修掉的两个

- **排序提示删掉**：原来拖完义项弹一句「顺序已变，进度没动」。
  顺序变了界面自己就变，而「进度没动」是在解释一件用户没问、也感知不到的事。
- **训练页按 query 变化重开一轮**：`/train` 与 `/train?solo=<id>` 是同一个
  路由组件，只差一个 query，`onMounted` 不会重跑 ——
  于是从单挑切回训练 tab 看到的还是刚才那轮的题。改成 watch query。

## 验证方式

每一条都是真机（vivo Y 系列，1260×2800 / CSS 360×800 / 密度 3.5）上量的：

| 项 | 判据 |
|---|---|
| 返回不成环 | 义项 → 单词 → 词库，`history.length` 与 hash 都对得上 |
| 深链返回 | `replaceState` 造 `#/word/x` 后刷新，`history.length===1`，返回落到 `/library` |
| 例句保护 | 未点任何东西时 `.sent [contenteditable=true]` 数量 = 0 |
| 键盘避让 | 只挪 43px 时页面滚 43px（原来一次 450px） |
| 导入闭环 | 更多 → 导入备份 → 系统选文件 → 确认 → 词数 18→19，快照与导入历史都对 |
| 跳转不闪 | screencast 逐帧：词库→单词页、单词页→义项页、义项页→返回、冷启动→单词页，四种切换都是**一帧直达**，中间帧字节数与稳定帧一致 |
