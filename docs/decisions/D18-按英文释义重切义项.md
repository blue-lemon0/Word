# D18 · 按英文释义重切义项（v2）

日期：2026-10

## 结论（先看这段）

1. **近义义项不是词典质量问题，是我们切错了。** ECDICT 中文侧把同义词平铺切开，
   按逗号切分就制造出「答复/回答/答辩」这种无法判别的假义项。
2. **英文 `definition` 是可靠边界来源。** 实测 3000 考研词里 98.0% 的词
   「英文行数 ≠ 中文段数」，中文侧粒度不可信。
3. **但纯按英文切会丢真义项** —— 351/2921 词（12.0%）存在「中文有某词性、
   英文零覆盖」。`author` 英文只有 1 条 `v. be the author of`，名词义「作家」完全没有。
   所以需要补洞规则。
4. **glossEn 已在管道里全程透传**（`build_bundle.py:128`，`CONTRACT.md §1.2` 已定义该字段），
   契约无需改动。但 **`version` 哈希不含 glossEn/pos**（`build_bundle.py:152`），
   不修则界面永远拿不到英文释义且**静默失败**。

## 为什么是两个词典

ECDICT 官方 wiki《双释义》写明两个字段来自**完全独立的两条管线**：

| 字段 | 来源 |
|---|---|
| `definition`（英文） | WordNet（普林斯顿）+ NodeBox。synset 级，天然一个义位一行 |
| `translation`（中文） | cdict-1.0-1.rpm + 屌丝词典（众包）+ 考试大纲词表 + Google 机翻 + CEDIT |

英文侧是 WordNet 的 synset，中文侧是机器翻译 + 众包词典平铺。粒度不一致是**结构性的**，
清洗修不了。反事实实测：按分号切会把义项总数从 17693 砍到 5746，
而分号只出现在 184/3000 词条且其中 179 条在会被跳过的 `[计]/[医]` 标记行里。
**「同义用逗号、不同义用分号」这条规则在 ECDICT 上是倒置的，不可用。**

  一旦合并同义英文行顺序就对上了。问题是粒度，不是错位。

## 【重要修正】不要因为「英文没覆盖」就舍弃义项

**这一节记录一次我做错并纠正的判断，避免以后重犯。**

我第一轮 decisions 里写了「舍弃」这个动作，理由是：

```
stone 宝石   ->「英文侧对应 gemstone，不是 stone」
stone 纪念碑 ->「英文侧对应 monument，不是 stone」
edition 翻版 ->「英文侧无独立义位」
```

**这是逻辑错误。** 我把两个命题混为一谈：

| 命题 | 是否成立 |
|---|---|
| ECDICT 的 `definition` 字段没收录这个义位 | ✅ 事实 |
| **英文里没有这个意思** | ❌ 我答错了 |

覆盖不足恰恰应该触发**保留**，不是丢弃。因为**词是用来造英语句子的，句子里的英文才是判据**，
不是 ECDICT 那一栏。验证：

```
stone = 宝石   → precious stone / semiprecious stones         真用法
stone = 纪念碑 → memorial stone / boundary stone / gravestone  真用法
stone = 结石   → kidney stone / bladder stone（calculus）      真用法
```

全部保留，`glossEn` 留空并在 note 标注覆盖缺失（`[glossEn 空：ECDICT definition 无对应义位]`）。
英文覆盖缺口只影响「有没有英文释义」，**永远不作为舍弃理由**。

### 由此加的硬约束：旧义项账目守卫

原设计里 decisions 写什么就产出什么 —— 现有 7884 义项中没被提到的会**无声消失**。
一个 25 行的批次就能吃掉别处的内容，这是最危险的失败模式。

现在每个现有义项必须在三种状态里**恰好出现一次**，否则 `--build` 直接失败：

```
fromZh 接住（保留中文释义）
_oldSenses action=merged  （并入某个英文义项，必须写 into + reason）
_oldSenses action=dropped （舍弃，必须写 reason）
```

这个守卫当场抓出了 6 个词的问题，也抓出我自己凭空编的 `stone 结石`
—— 现有库里根本没有这个义项，是我看的是 ECDICT 原始 translation 而非发布后的库。

## 采纳的规则

```
1. 英文 definition 逐行成义位边界（真相源）
2. 同义英文行合并（capital 的 raw=0 与 raw=1 都是「资本」）
3. 清洗（显式开关，全在 spec.yaml 的 senses_v2: 段）
   - 互见行 "See X"          丢弃
   - 百科/专名条目            丢弃
   - 正文 < 4 词             丢弃
4. 补洞：英文对某词性零覆盖时，该词性从现有中文义项补入，note 标 ZH-FALLBACK
5. 守卫：每个现有义项必须被接住/说明合并/说明舍弃，否则 build 失败
```

第 4 条是试点中途加的。依据：

```
英文零覆盖某词性的词: 351 / 2921 (12.0%)
  a 111 / n 108 / v 97 / num 20 / adv 12 / prep 5 / conj 3 / pron 3
  author  T1 英文仅 1 边界 v. be the author of  -> 名词义「作家」全丢
  social  T1 英文 4 条全是 a.                    -> 名词义「联欢会」全丢
  capital      英文无形容词义位                   -> 首都的/重要的全丢
  queen        英文无动词义位                     -> 立为女王/做女王全丢
```

这**不是**回头用中文切分（那会回到过度切分），而是在英文缺位时不假装它不存在。
补进来的义项来源可查、可回退。
