# D34 —— 固定栏与橡皮筋：能同时要「弹」和「栏不动」吗

> 决策日期：2026-10-18
> 一句话：**不能，而且这不是网页平台的限制 —— 是「橡皮筋」这件事本身
> 作用在窗口层。要栏不动如山，就只能不要橡皮筋。**

---

## 1. 问题

用户反馈：网页里有个能滚的列表，滚到边缘继续拖，顶栏和底部 tab 栏会
「短暂有部分被拖到屏幕外」，有弹性感；而原生 app 里同样操作，栏**不动如山**，
只有列表在弹。问：网页里是不是注定做不到？

## 2. 先量，别猜

肉眼判断不了这件事（越界拖动只有一两帧，`adb screencap` 必然错过）。
用 `tests/overscroll_probe.mjs` 在真机上同时量两样：

| 量什么 | 怎么量 | 能回答 |
|---|---|---|
| **DOM 位移** | 越界拖动期间每 10ms 采一次 `.fixed` / `.sb` 的 `getBoundingClientRect().top` | 固定栏在**网页这一侧**动没动 |
| **合成器位移** | 同一段手势用 CDP `Page.startScreencast` 逐帧录 | 屏幕上到底动没动 |

本机（1260×2800 / dpr 3.5 / targetSdk 36）实测：

```
doc  down  底栏 .fixed 位移 : 0 px   状态栏 .sb 位移 : 0 px   scrollY 变化 : 0 px
doc  up    底栏 .fixed 位移 : 0 px   状态栏 .sb 位移 : 0 px   scrollY 变化 : 0 px
sheet down 弹层体 .sh-b 位移 : 0 px   底栏 / 状态栏 : 0 px
```

**DOM 一动没动，scrollY 也一动没动。** 这条测量就是全部结论的地基：
「栏被拖走」这件事从来不是 DOM 干的，网页侧也就无从「改好」它。

## 3. 两套机制，分开看

### 3.1 DOM 侧（网页能控制的那一半）

默认滚动容器是 `<html>`。越界拖动时，浏览器**不移动文档**，`scrollY`
不会变成负数也不会超过上限 —— 所以 `position: fixed` 的栏天生不动。
这一半由 `overscroll-behavior` 决定：

| 值 | 本地橡皮筋 | 传给祖先 |
|---|---|---|
| `auto` | 有 | 有 |
| `contain` | **有** | 无 |
| `none` | 无 | 无 |

### 3.2 窗口侧（网页看不到的那一半）

`targetSdk ≥ 31` 时 Android 默认开 `crossWindowStretchEffectsEnabled`。
当 WebView 向系统报告越界，**系统给整个窗口做拉伸位移**。
这个位移作用在窗口合成上，发生在 DOM 之外：网页既观测不到、也改不了。

**这就是「栏会跟着动」的唯一原因**：橡皮筋之所以能让栏动，
恰恰因为它是**整个窗口在动**，而固定元素就长在这个窗口里。

> 所以「fixed 就该不动」这个推理在这条链上是断的 ——
> fixed 相对的是**视口**，不是**窗口**。

## 4. 原生为什么不一样

原生（RecyclerView）的回弹是在**列表自己内部**做的：AppBar 和底栏
不是列表的祖先、不在它的绘制范围里，于是「列表弹、栏不动」是天然的。

网页想抄这个结构并不难：内容区做成独立滚动容器、栏做成它的兄弟节点。
但**前提仍然是 Chromium 的越界效果作用在哪一层** ——
Android 上它只在根滚动容器（`<html>`）上有可见效果，内层容器做不出
原生那种回弹。所以「独立滚动容器」这条在网页里换不到那口气。

## 5. 结论（二选一，没有第三条）

| 要什么 | 怎么做 | 代价 |
|---|---|---|
| **栏不动如山**（本项目选的） | 根滚动容器和所有内层滚动容器一律 `overscroll-behavior: none` | 越界拖动**完全没有反馈**：不回弹、不发光、像撞到一堵墙 |
| 保留橡皮筋 | 什么都不做 | 栏跟着窗口一起被拖走 |
| 两者都要 | **做不到** | — |

「不可滚动的页面没有这个问题」不是巧合，而是同一件事的另一面：
没有可滚的内容就没有越界，也就没有橡皮筋。

## 6. 这次顺手修掉的一个「注释与生效值不一致」

原 `style.css` 写着：

```css
html {
  overscroll-behavior: none;
  overscroll-behavior-y: contain;   /* ← 后写的长写把 y 轴覆盖成了 contain */
}
```

注释声称「橡皮筋已禁在 html 上」，真机 `getComputedStyle` 量出来却是
`html_y: "contain"`。作者把 contain 理解成「禁橡皮筋」，实际它只禁「往上传」。

两处都改了：

- `style.css` 的 html 去掉 `overscroll-behavior-y`，只留 `none`，
  并把上面那段错误的解释改对；
- `components/Sheet.vue` 的 `.sh-b` 补上 `overscroll-behavior: none`
  —— 全站仅有的第二个滚动上下文，原先是默认的 `auto`（两个口子：
  自己会弹 + 越界传给祖先）。

**教训与坑 42 同源：注释不能当判据。** 这类不一致不会报错、不会留痕，
只有 `getComputedStyle` 量一下才知道。已加进
`scripts/verify_docs.py` 的真机交互守卫（39 项）。

## 7. 验证与回归

```bash
node app/web/tests/overscroll_probe.mjs doc down     # 根滚动容器，到顶继续下拉
node app/web/tests/overscroll_probe.mjs doc up
node app/web/tests/overscroll_probe.mjs sheet down   # 需先在真机上打开底部弹层
```

判据：`底栏 .fixed 位移 : 0 px` 且 `状态栏 .sb 位移 : 0 px`。
偶发帧（同一时间点 DOM 数字为 0、而逐帧录屏里位置变了）说明动的是
合成器/窗口 —— 那属于 3.2，网页侧无解，要断就在原生
`setOverScrollMode(View.OVER_SCROLL_NEVER)`。

## 8. iPhone（PWA 那条路）

`overscroll-behavior` 需要 Safari 16+。更早的 iOS 用的是 body bounce，
网页侧的兜底是给 `body` 加 `position: fixed`（会把滚动容器换成 body，
代价大）。本项目不支持 iOS 16 以下，这条只作记录，不实现。
