## 一句话结论

**保持 ECDICT 为主源，切分边界改用它内嵌的 WordNet 3.0 释义。**
不换源。理由不是「换源麻烦」，是**换源解决不了主要问题，还会引入新问题**。

## 三个问题的答案

### Q1：为什么会有大量相似义项？

ECDICT 的 `definition` 与 `translation` 来自**两条完全独立的管线**，
这一点 ECDICT 官方 wiki《双释义》写得很清楚：

| 字段 | 来源 |
|---|---|
| `definition`（英文） | **WordNet 3.0** + NodeBox |
| `translation`（中文） | cdict-1.0-1.rpm + 屌丝词典（众包）+ 考试大纲词表 + Google 机翻 + CEDIT |

英文侧是 WordNet 的 synset（一个 synset = 一个义位），中文侧是机器翻译 + 众包词典平铺。
粒度不一致是**结构性的**，实测：

```
3000 考研词：
  英文行数 != 中文段数 的词: 2939 / 3000 = 98.0%
  每个 pos 组内两边数量都相等:   44 / 3000 =  1.5%
  英文比现有义项多 >=2 个:     1010 词
  英文比现有义项少 >=2 个:      262 词
```

**「同义用逗号、不同义用分号」这条规则在 ECDICT 上是倒置的，不可用。**
分号只出现在 184/3000 词条，且其中 179 条在会被 `SKIP_TAGS` 跳过的 `[计]/[医]` 标记行里。
实测按分号切会把义项总数从 17693 砍到 5746 —— 而 capital、fan、rock 会被压成单义项。

### Q2：词性已经有了吗？

有，100% 覆盖，`pos` 从不缺值：

```
n. 4931 / a. 1374 / vt. 904 / vi. 309 / adv. 162 / v. 150 / num. 30 / prep. 11 / conj. 7 / pron. 6
```

英文侧的词性标记也齐全：`n. 2122 / v. 460 / a. 224 / s. 130 / r. 56 / adv. 3 / prep. 2 / pron. 2`。
注意 ECDICT 用罗杰特体系的 `s.`=形容词、`r.`=副词，需归一化。

### Q3：为什么还有舍弃义项这个决策？

**这个决策不存在。我曾犯错，已纠正。**

我第一轮 decisions 里写了「舍弃」，理由是「英文侧对应 gemstone，不是 stone」。
这是逻辑错误 —— 我把两个命题混为一谈：

| 命题 | 成立 |
|---|---|
| ECDICT 的 `definition` 没收录这个义位 | ✅ 事实 |
| **英文里没这个意思** | ❌ 答错 |

验证：`precious stone`、`memorial stone`、`kidney stone` 全是真实英文用法。
**词是用来造英语句子的，句子里的英文才是判据，不是词典某一栏。**

由此加了硬约束 —— **旧义项账目守卫**：每个现有义项必须在三种状态里恰好出现一次
（`fromZh` 接住 / `_oldSenses action=merged` / `action=dropped`），否则 `--build` 直接失败。
原设计里 decisions 没提到的义项会**无声消失**，一个 25 行批次就能吃掉别处的内容。

这个守卫当场抓出 6 个词的问题，还抓出我凭空编的 `stone 结石`（现有库根本没这个义项 ——
我当时看的是 ECDICT 原始 translation，不是发布后的库）。

### ECDICT 英文侧够用吗？—— 已用 WordNet 3.0 逐词核对

已下载 WordNet 3.0（NLTK 包，10.28 MB）vendor 到 `content-kit/source/wordnet/`，
逐词对比 2859 个词：

```
ECDICT 英文义项总数 8439 (平均 2.95/词)
WordNet  英文义项总数 12827 (平均 4.49/词)

逐词集合比较:
   两者相等    1797 词 (63%)
   WordNet 更多 1010 词 (35%)
   ECDICT 更多   52 词 (2%)
```

**结论：ECDICT 英文侧 = WordNet 的一个子集，导入了约 2/3。**
丢失的 35% 里既有我们要的（`author` 的 `writer.n.01` / `generator.n.03`，
ECDICT 只留了 `author.v.01 be the author of`），也有大量噪声
（`well` 多 21 条、`make` 多 30 条，多为固定语块与罕见义）。

已验证 ECDICT 的 definition 就是 WordNet 逐字原文 —— 连 `capital` 那条多余的
尾引号 `upper-case letters"` 都原样带过来。所以两者可直接互相校验。

### 为什么不换源：WordNet 单独用会有三类新问题

**① 专名/百科条目**

```
stone  WordNet 16 synsets，其中 5 条是美国人名
       stone.n.07 United States jurist who was named chief justice...
       stone.n.08 United States filmmaker (born in 1946)
queen 12 synsets 含 queen.n.07 扑克牌 Q、queen.n.08 国际象棋后
capital 11 synsets 含 das_kapital.n.01 《资本论》、capital.n.06 美国联邦政府
```

**② 罕见义 / 语域义**

```
more   (comparative of `many' used with count nouns) quantifier meaning great
can    a buoy with a round bottom and conical top   （浮标）
will   a legal document declaring a person's wishes（遗嘱）
```

**③ 固定语块被当义项** —— `make` 多出的 30 条大量是 `make up`/`make out` 之类。

这些正是 `spec.yaml` 的 `senses_v2:` 段里那几个清洗开关要拦的。
**ECDICT 已经替我们做了一轮筛选**（它把专名和罕见义挡掉了大部分），
所以「ECDICT 为主 + WordNet 补缺」比「纯 WordNet」更省事也更干净。

## 最终方案

```
切分边界  ECDICT definition（= WordNet 3.0 子集，已清洗过）
补缺      WordNet 3.0 补 ECDICT 缺失的义位（先过滤专名/罕见义/语块）
中文释义  AI 按英文义项翻译生成（不再靠位置配对，只有 1.5% 能对上）
词性      从英文行首标记取，s.→a. / r.→adv.
```

产出目录 `content-kit/data/senses_v2/`，现有 `data/wordlist/senses/` 一字未动。
语义决策落 `data/senses_v2/decisions/<word>.json`（数据不是代码），
所有开关落 `spec.yaml` 的 `senses_v2:` 段。

## 一个必须说清的事实：现有义项数是被「每词上限」截断出来的

这点决定了重切时不能无脑用 WordNet 的全部义项。

```
词数与档位（真相源是 data/wordlist/senses/*.tsv，不是 core.tsv —— 后者 tier 全是 CORE）:
   T1  663 词 x 每词上限 4 = 2652
   T2 1218 词 x 每词上限 3 = 3654
   T3 1011 词 x 每词上限 2 = 2022
   T4  106 词 x 每词上限 1 =  106
   合计 2998 词, 上限合计 8434, 实际义项 7884 → 利用率 93.5%

实际 tier 分布（义项级）:
   T1 2401 (30.5%) / T2 3427 (43.5%) / T3 1950 (24.7%) / T4 106 (1.3%)
```

**现有 7884 个义项不是「词有多少义项」，而是「每词最多留 N 个」的截断结果。**
而 WordNet 的义项数（平均 4.49/词）远超这个上限。所以重切时必须**沿用同一套
每词上限做优先级截断**，否则一个 `well` 会带进 21 个义项。

截断优先级建议（按价值排序）：
```
1. 高频义（WordNet sense number 小 = 语义标注语料里更常见）
2. 有例句可造 / 考研语境常见
3. 与其他义项可判别（不产生新的同义重复）
```

`keep_per_tier` 应写进 `spec.yaml` 成为显式配置，而不是散在代码里。
