# D56 —— 页面口径按页面职责，不做全站强制统一

> 决策日期：2026-10-31
> 一句话：**词库页回答「哪些词要处理」，训练页回答「这一轮还有几张卡」；两个页面用不同单位是设计，不是不一致。**

---

## 一、问题

多义词让「词 / 义项」两个口径天然同时存在：

- 词库是**台账**，用户按词找、按词看内容，一个词有 3 个义项也只占一行；
- 首页「复习 / 学习」和训练页是**出题队列**，一张卡 = 一个义项。

如果为了「看起来统一」把全站都改成词数，训练时练掉一个义项、词数可能纹丝不动，
用户会觉得「刷了半天没进度」；反过来全站都改义项数，词库又会失去按词管理的意义。

## 二、决定

按页面职责分别选择主口径，**不追求全站一个数字**：

| 页面 | 主口径 | 次口径 / 说明 |
|---|---|---|
| 词库页顶部 | **词**（今天到期 / 新词 / 待学） | 括号里给义项数，如 `3 个词到期（8 个义项）` |
| 词库页按钮 | **词** | `复习这 3 个词` / `学这 2 个词` |
| 首页复习 / 学习 tab | **义项**（出题张数） | 与队列同源；答一卡实时减一 |
| 训练页顶部 | **义项**优先 | `第 3/10 题` + `剩 8 义项 / 3 词` |
| 词条 / 义项页 / AI 提示词 | **义项** | 这里是内容模型，需要精确 |

术语同理：词库偏「词」，训练与内容维护偏「义项」；
`这句话是什么意思` 这种自然语言保持「意思」，不做机械替换。

## 三、以后怎么改

1. **禁止全站批量替换文案或计数单位。** 一次改一处、先看那个页面的职责。
2. 改之前先确认：这个页面是台账、队列，还是内容模型？主口径跟着职责走。
3. 守卫只守行为，不强制全站一个术语；不要为了「统一」把页面的设计差异磨平。
4. 任何跨页面的文案 / 口径改动，先征得确认再动手，不擅自扩大范围。

## 四、判据

- 词库仍按词分组、按词显示主数字；义项数只能作为括号里的补充。
- 训练页仍显示义项进度（第 X/Y 题、剩余义项/词），不能退回纯词数。
- 不同页面的称呼允许不同，但同一页面内部不能混用两种主口径。
