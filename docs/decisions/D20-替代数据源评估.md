# D20 · 替代数据源评估（除 ECDICT / WordNet 之外）

日期：2026-10
状态：**调研完成。结论：不换源。** 现有内容一字未动。

## 一句话结论

**没有更好的开源源。** 逐个评估了 6 类候选，唯一在「单一来源 + 逐义项对齐 + 中英双语 +
许可宽松」四项全过的是**付费的 LDOCE/OALD 双语版**。其余各有硬伤。

## 候选逐项评估

### ① CC-CEDICT —— 唯一「正确实现同义/义项分隔」的免费源

**这是本次调研最有价值的发现。** CC-CEDICT v2 的格式规范明确写了：

> "A definition is made up of senses, and a sense is made up of glosses.
>  **Senses should be separated using a slash "/", while glosses should be
>  separated with a semicolon ";"**. ... glosses within a sense are
>  **synonyms** ..., while senses represent **wholly different meanings**."

也就是说 **CC-CEDICT 用「/」分隔义项、「;」分隔同义译词** —— 正好是你一开始说的那套规则，
而且它**真的实现了**。这与 ECDICT 的做法完全相反（ECDICT 拿它当中文侧原料，
再用逗号把同义词平铺切开，于是破坏了 cdict 原有的义项结构）。

但对我们**不可用**，三个硬伤：

```
1. 方向反了。CC-CEDICT 是「中文 → 英文」，我们要的是「英文 → 中文」
2. 无词性标记。规范的 Rules 明确说："Don't use parts of speech"
3. 无英文释义。只有中文 + 对应英文词形，没有 definition
```

第 3 条致命 —— 我们要靠英文释义定边界。

许可：CC BY-SA 4.0（free but not very open；作者明确不希望被批量抓取，
导出文件页面声明 scraping is not allowed）。

### ② 有道词典 `jsonapi` —— 技术上完美，法律上不能碰

```
https://dict.youdao.com/jsonapi?q=<词>
无需 key、无需登录、无配额。一次返回 45KB / 29 个内容区块。
```

返回的 `longman`（朗文当代高级英语辞典）字段结构**正是我们要的**：

```json
"Sense": { "DEF": "详细英文释义", "SIGNTRAN": "翻译", "EXAMPLE": "例句" }
"Head":  { "POS": "词性", "FREQ": "频率 S1/W1…" }
```

同一个 Sense 下 `DEF`(英) 与 `SIGNTRAN`(中) 成对 —— **这才是真正的「单一来源、
逐义项对齐、双语」。** ECDICT 缺的就是这个。

**但不能用。** 有道是商业产品：
- `openapi.youdao.com` 正式通道需 appKey + 签名，且属智云商业服务
- 官方明确「由于第三方合作及版权等因素，有道无法提供柯林斯/朗文数据服务」
- 牛津、韦氏等区块是**加密下发、版权保护**的内容
- 网上文章明确提醒不要批量抓取

用它 = 把商业版权内容洗进开源仓库，且依赖一个随时可能变更的私有接口。
**这跟本项目「离线可备份、可复现」的铁律直接冲突。**

### ③ 考研专用词表（NETEMVocabulary / 红宝书 JSON）

```
exam-data/NETEMVocabulary:  5530 考研大纲词，按 200 套真题词频排序
                            「释义经过了人工初步校对」但只有中文，无英文释义
2027-kaoyan-english-redbook-json:  不背单词 APP 的红宝书 PDF 提取
```

思路对（真题词频 + 人工校对 + 专供考研），但：
- **只有中文释义，没有英文 definition** —— 无法用来定边界
- 分号/逗号混用的中文长串，仍需重新切分
- 数据来源是 PDF / 他人爬取成果，许可与可持续性都不明

**可以借鉴的只有一点：真题词频排序。** 这对我们的义项优先级排序有用
（比按字母序或字典序更贴近「考研真的会考」）。

### ④ Wiktionary（Wiktextract / kaikki.org）

```
免费、CC BY-SA、逐义项、有英文 gloss、有例句。
```

但核心问题正是双语对齐 —— LREC 论文原文：

> "a sense description associated with translations ... is often not
> identical to any gloss and **often uses a different sense granularity**"

即：中文译文挂靠的 sense 描述，与英文 gloss **粒度不同、经常对不上**。
这跟我们用 ECDICT 遇到的是同一类问题，只是换了个形态。en 版 dump 约 1.9GB。

### ⑤ Merriam-Webster API —— 收费且无中文

```
免费档：非商业用途、1000 次/天、限 2 个 reference API。
Learner's Dictionary 有完整的 sense 层级（def[].sseq[].sense，含 dt/vis/snote）
且音频、例句齐全 —— 但**没有中文释义**，仍是单语源。
```

### ⑥ LLM 生成的开源英汉词典（ahpxex/open-e2c-dictionary）

```
25,318 个 JSON 词条，Qwen3-Next-80B 生成，
每条含 explanation_en + explanation_cn + example_en + example_cn
```

**这是唯一一个「双语逐义项」且格式完美的免费源。** 但：
- 只有 25,318 词，覆盖我们的 2998 考研词需要逐个核对
- **AI 生成的释义会继承模型的幻觉** —— 用它当真相源，等于用一个不可验证的东西
  替换另一个不可完全验证的东西
- 我们自己就在做「英文切分 + AI 生成中文释义」这件事，重复造轮子

## 为什么「单一来源」这个诉求本身是对的，但换源解决不了

你最初的判断 —— 「最好是找到一个可靠的单一来源，都提供两种释义」—— **完全正确**。
LDOCE/OALD 双语版就是这个，而且它就是商业背单词 App 的做法：

```
OXFORD 牛津高阶 / LDOCE 朗文当代高级 —— 双语版每个义项下英文定义 + 中文对译，
同一个义位，不存在对不上的问题。因为它本来就是一本词典的同一页汉典/有道/柯林斯中文版。
```

**免费世界里没有这个东西。** 所有免费双语词典都是**把两本不同的词典拼在一起**，
然后你就得到了我们正在处理的那个问题。CC-CEDICT 最接近（有正确的 sense/gloss 结构），
但它是中文→英文且不标词性。

2998 词我可以全部过一遍。这是决定性优势，不是安慰话。

## 补充调研：WordNet 补缺的可行性（量化）

既然不换源，那 WordNet 能补多少、噪声有多少？我做了细查：

```
T1/T2 词的 WordNet 独有义项: 9380 条 (T1=3274 T2=6106)

按 lexname 分布（这是最有用的过滤信号）:
   adj.all 1384 (14.8%)  noun.artifact 637  noun.act 599  noun.communication 504
   verb.change 432  verb.contact 424  verb.communication 417  verb.motion 336
   noun.cognition 328  verb.social 324  noun.person 286 …

usage_domain 标记（语域受限）: 101 条 (1.1%)
   colloquialism 46 / plural 17 / slang 11 / archaism 10 / combining_form 4
```

关键发现：**`usage_domain` 几乎抓不到噪声**（只有 1.1%），
因为 `can = 浮标`、`will = 遗嘱` 这类义项 WordNet 并没打语域标签。
所以**不能靠 WordNet 的元数据自动判断「这个义项重不重要」** ——
这也是为什么 `--plan` 里的清洗开关必须是显式配置 + 逐词人工确认，而不是黑盒规则。

`noun.person` + 含 "United States" 的（专名人名）只有 299 条 (3.2%)，
比正则清洗（65 条 ECDICT 内）更少，但能覆盖正则漏掉的（如 `student`/`child`/`man`
这些 `noun.person` 里其实是正常义，不是人名）。

### hyponym 关系能解释「宝石/纪念碑」吗？能

```
stone.n.02 (building material) 的 hyponyms: grindstone, gravestone, headstone,
                                          tombstone, paving_stone, springer
```

所以 `stone 纪念碑` = gravestone/tombstone，是 stone 的下位概念。
这印证了机制一（WordNet 把「可推导的细分」存成 hyponym 指针，不建独立义位）。

**但这不构成保留或删除的理由** —— 上一轮已经定了：词是用来造句的，
`a memorial stone stands in the yard` 和 `he threw a stone` 是两个毫不相干的场景，
推理得出来不等于教得出来。hyponym 信息可以写进 note 供我判断，但不作判据。

## 最终方案（不变）

```
切分边界  ECDICT definition（= WordNet 3.0 子集，已被筛过一轮）
补缺      WordNet 3.0 补 ECDICT 缺失的义位（按 lexname 过滤 noun.person，
          按显式开关过滤；重要性由人工逐词判断，不靠黑盒）
中文释义  AI 按英文义项翻译生成
词性      从英文行首标记取，s.→a. / r.→adv.
每词上限  沿用现有 keep={T1:4,T2:3,T3:2,T4:1}，写入 spec.yaml
```

## 可借鉴的两点外部经验

1. **真题词频优先**（NETEMVocabulary 的做法）：义项优先级不按字母序，
   按 200 套真题里的实际出现频次。这对「哪些义项值得写 5 句」有直接价值。
2. **CC-CEDICT 的 sense/gloss 二级结构**：如果将来拿到任何「按义项切好」的
   中文源，这个格式可以直接采信 —— 它比 ECDICT 的中文侧可靠。
