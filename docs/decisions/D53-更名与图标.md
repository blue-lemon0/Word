# D53 —— 正式更名「极简单词」+ 图标换成真素材

> 决策日期：2026-10-19
> 一句话：**应用名从「词库」改为「极简单词」；图标不再由代码画，改为位图母版 + 脚本派生。**

---

## 一、更名

| 位置 | 现在 |
|---|---|
| Android `app_name` | 极简单词 |
| 网页标题 / `apple-mobile-web-app-title` | 极简单词 |
| PWA `manifest.webmanifest` | `极简单词 · 背单词` / `极简单词` |
| 包名 | **不动**：`com.wordbank.app.debug` |
| 文档里的「词库」 | 保留 —— 它指的是**用户的词库**（概念），不是应用名 |

**为什么不动包名**：改包名 = 系统里变成另一个应用，本地 IndexedDB 里的学习进度会「丢」。
名字是给用户看的，包名是给系统看的，两者不必一致。

## 二、图标：从「代码画」改成「位图母版 + 派生」

原来的 `scripts/make_icons.mjs` 是用 SVG 画一个渐变色块 + 字母 —— 那只是占位。
现在有正式素材，于是改成**位图流水线**：

```
边角留白已裁掉的方形图（1024）
├── public/icon-master.png   满幅方形、圆角外用深蓝涂满  → 旧式启动图标 / PWA 普通图标
└── public/icon-glyph.png    透明底、只有白纸片与色块    → Android 自适应图标前景层
        ↓ npm run icons / npm run icons:android
   public/icon-64|192|512.png、maskable、apple-touch、favicon.svg
   android res/mipmap-*/ic_launcher.png（48/72/96/144/192）
   android res/mipmap-*/ic_launcher_foreground.png（108dp：108/162/216/324/432）
   android res/mipmap-anydpi-v26/ic_launcher(.round).xml + colors.xml 的 #1f2a44
```

**裁留白的口径**：源图四周是 `#f3f4f6` 的浅灰边，按「所有通道 > 235 视为背景」求包围盒，
裁出内容后统一缩放到 1024。圆角外那圈浅灰在母版里涂成深蓝 `#1f2a44` —— 否则旧式图标
四个角会露出浅灰（系统不会替我补）。

**为什么自适应图标要拆两层**：前景层必须只有图形、底色交给 `background`。
直接把「满幅方形图标」当前景，系统再套一层遮罩，圆角外的底色会跟遮罩打架，看起来脏。

## 三、今天踩到的两个坑（写进代码注释了）

1. `mipmap-anydpi-v26/` 之前是**空目录** —— 只有 PNG，没有自适应描述文件。
   于是 Android 8+ 仍按旧式图标处理，圆角/圆形遮罩下会露出灰边。
2. 图标脚本会**覆盖**产物：旧的 `make_icons.mjs` 一跑就把手绘图标写回去。
   更换素材后必须同步改脚本，否则「跑一次全白做」。

## 判据

| 断言 | 拦什么 |
|---|---|
| `app_name` = 极简单词 | 更名漏改 |
| `res/mipmap-anydpi-v26/ic_launcher.xml` 存在且引用 `@mipmap/ic_launcher_foreground` | 自适应图标退化 |
| `public/icon-master.png` 与 `icon-glyph.png` 存在 | 母版丢失，脚本无法重跑 |
| 两个图标脚本都读母版、不再画 SVG | 又回到手绘占位 |
