# D35 —— 信息架构：底栏的语义，与清单的长度

> 决策日期：2026-10-18
> 一句话：**二级页不摆底栏；会变长的清单必须有自己的滚动框。**
> 两条是同一条原则的两个应用 —— **界面结构不该由「控件长什么样」或
> 「数据有多长」决定，该由「用户以为这是什么」决定。**

---

## 一、二级页收底栏

### 现象

从首页 / 词库钻进单词页、意思页、错题板之后，底部 tab 栏还在。
用户反馈：这个后退栈太混乱了。

### 为什么底栏出现在二级页是错的（这才是真问题）

底栏在手机上被读成「**和我同级的四个地方**」。二级页里也摆着它，
就同时产生了两种错误预期：

| 预期 | 实际 |
|---|---|
| 「点一下当前高亮的那项，是回到上一层还是原地不动？」 | 路由跳走，和点别的 tab 一样 |
| 「在二级页里点另一个 tab，是**替换**当前页还是**压一层历史**？」 | 压一层 —— 路由变了、历史又多一格 |

第 2 条要命：从意思页点「词库」，返回键会退回意思页。
同一个页面来来回回，后退栈越按越长。这不是实现 bug，
是底栏这个控件的语义与「详情页」天生冲突。

### 做法

- 只有 `/`、`/library`、`/train`、`/more` 四页有底栏；
  `/word/*`、`/sense/*`、`/board` 一律收。
- **`v-if` 而不是 `v-show`**：v-show 留着元素只改 display，
  切换那一帧页面底部会突然多/少一截空白 —— 一次可见的跳变（坑 42）。
- **收底栏必须同时收回它占的那块留白**，否则内容底部凭空多一截空白。
  做法是改 `--wb-tabbar-h: 0px` 这**一个**变量：`.wb-page` 的
  `padding-bottom`、首页 `.home` 的 `min-height`、`.toast` 的落点
  全都是按它算的，逐处加 `if` 只会漏掉一处，而漏掉的那处
  表现恰恰是「底部多一截空白」。
- 改类名用 `watch(..., { flush: 'sync' })`：必须赶在渲染之前，
  晚一帧就是坑 42 说的那种跳变。

### 放弃了什么

二级页里不再能一键跳到别的 tab。代价是「在意思页想去词库」要多按一次返回。
换来的是后退栈只有一条线：从哪来回哪去。

### 真机验证

```
/  /library  /train  /more   →  tabbar:true   no-tabs:false   --wb-tabbar-h: 50px
/word/army                   →  tabbar:false  no-tabs:true    --wb-tabbar-h: 0px   padding-bottom: 16px
/sense/<id>                  →  tabbar:false  no-tabs:true
/board                       →  tabbar:false  no-tabs:true
```

切页与返回逐帧录屏：进二级页 2 帧、回退 2 帧，**无中间帧**
（`screencast_frames.mjs`，28.8 KB → 49.8 KB 直接到位）。

## 二、会变长的清单必须有自己的滚动框

### 现象

更多页的「快照」「导入历史」「回收站」直接平铺，长度不由界面决定。

### 为什么这是个真问题（真机实测）

| 组 | 行数 | 高度 |
|---|---|---|
| 备份 | 3 | 210px |
| 快照 | 6 | 312px |
| 导入历史 | 6 | 440px |
| 回收站 | 2 | 120px |

18 词的小库就已经 **1637px vs 视口 800px**（两屏半）。而且：
快照封顶 10 条还好，**导入历史只增不减**、**回收站要等 30 天才清** ——
都是无上限的。「更多」是低频页，为了看第 8 条快照要滚过整页。

### 做法

- **一个卡片、三个平级面板**：快照 / 导入历史 / 回收站，左右滑动切换。
  它们本来就是一类东西 —— 都是「已经发生过的、会留痕的记录」，逐条操作
  也都是无害的（回滚 / 看 / 还原）。唯一带破坏性的「清空回收站」
  本来就走确认弹层，而滑动阈值是三成屏宽，**误触切屏和误触删除不会同时发生**。
- 每组各自套 `.cap-list`：`max-height: 236px; overflow-y: auto`。
- **条数写在滚动框外面**（滑动容器的分段标题上）：
  被裁掉多少是**看不见的**，只给一个会滑动的框，
  用户不知道里面还有东西，于是要么反复滑、要么以为就这些。
- 用**固定像素**而不是 `calc(...vh)`：这个框在页面中间，
  按视口算会随状态栏、键盘、软键盘高度全变，页面长度就不可预期了。

### 三个面板同时渲染，不做懒加载

坑 42 说过「第一帧不管渲染什么都是跳变」。懒加载的滑动容器，
切过去的第一帧就是一个空面板 —— 正是那种跳变。

### ★ `overscroll-behavior-y` 这里是 `auto`，不是 `none`

第一版按 D34 的结论给所有内层滚动容器写了 `none`，结果**页面滚不动了**：

```
清单框里竖向拖：清单 0 → 52（全部余量）→ 停住，页面 0 → 0（不动）
```

`none` 不只关橡皮筋，**它把「滚动传递」也关了**。
而传递和橡皮筋是两件事 —— 橡皮筋的最终受害者是**窗口**（系统拉伸），
传递的受害者只是**祖先滚动容器**。

判据是这个框**下面是什么**：

| 框 | 下面 | 用什么 |
|---|---|---|
| 更多页的 `.cap-list` | **页面** | `auto`（要传递；橡皮筋仍然不来，因为文档是 `none`） |
| `Sheet.vue` 的 `.sh-b` | 一层遮罩 | `none`（传递过去会拖动背后的整页） |

这两条同时挂进守卫 —— 只断言一条的话，下一个人照样会把另一条抄过去。
完整判读见坑 46。

### 真机验证

```
/  /library  /train  /more   →  tabbar:true   no-tabs:false   --wb-tabbar-h: 50px
/word/army  /sense/<id>  /board → tabbar:false no-tabs:true   --wb-tabbar-h: 0px   padding-bottom: 16px
```

切页与返回逐帧录屏：进二级页 2 帧、回退 2 帧，**无中间帧**。

更多页滑动容器：

```
向左滑 ×1 → 导入历史   track: translateX(-33.3333%)
向左滑 ×1 → 回收站
再向左滑 → 不动（末屏不给界位移）
点分段标题 → 快照
清单框竖向拖：清单 0 → 52 → 页面 0 → 48（传递生效，页面没被堵住）
```

页面高度：**1637px → 847px（1.1 屏）**。

### 放弃了什么

内层滚动在移动端天生难伺候（滚错层、滚动传递）。接受它，
因为这三个是**日志**而不是内容 —— 日志就该有个上限和明确的总数。
