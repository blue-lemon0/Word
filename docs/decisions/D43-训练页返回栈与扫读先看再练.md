# D43 —— 训练页的返回栈，与扫读「先看答案再问练不练」

> 决策日期：2026-10-19
> 一句话：**同一页内部的切换不许往历史里塞格子；扫读点一行先给答案，再问要不要练。**

---

## 一、返回栈为什么「有问题」

训练页里其实有四种「进入」，它们原来用的是同一套方式（都 push 一个新路由条目）：

```
首页「去训练」      → push /train
词库「练这组」      → push /train?scope=due
扫读点一句          → push /train?solo=..&sent=..
错题板「单挑这个意思」→ push /train?solo=..
```

第 3、4 种是**在同一页内部换内容**，却各自多占了一格历史。后果有两个：

1. **返回键看起来没反应**：从扫读点进单题后按返回，路由回到 `/train`（没有 query），
   而组件状态还是那道题 —— 于是画面不变。用户以为返回坏了，再按一次才真的退出训练。
2. **历史越按越长**：点三句扫读就多三格，每格都是同一页的另一个状态。

修法（一条规则）：**同一页内部的切换用 `replace`，只有从别的页面进来才 `push`。**

- 扫读点一句 → `replace`（它就在训练页里）
- 词库「练这组」→ `push`（从别的页面进训练，返回该回词库）
- 而且 query 被清掉时必须**复位到「怎么练」**：这才是「返回」应该看到的东西。

再补一层：在「单挑 / 扫读点进来」的那一轮里，**顶栏返回的第一下是回到「怎么练」**
（扫读列表就在那一屏，人还想继续扫），第二下才退出训练。
这一层用 `backToPicker()` 实现，它同时把 query 清掉（用 replace，不加历史）。

## 二、扫读点一行：原来直接跳进答题，现在先给答案

**原来的流程**：点一行 → 立刻进单题（显示选项 → 选 → 判对错 → SRS → 结算屏）。
想「只看一眼这句什么意思」的人，被迫先做一道题；做完还要看一个
「这一轮练完了 · 1 题 · 正确率 100%」的结算屏。

**现在**：点一行 → 浮层（`ScanPeek`）：

```
reply                          n.  3 句
The manager replied to my email within an hour.
经理在一小时内回复了我的邮件。
────────────────────────────
n.  回答，答复
────────────────────────────
[继续扫]              [练这一句]
```

- 想查就查个够：英文高亮、中文翻译、**这句里那个词的意思**（这里是「查」，不是「考」）；
- 想练再点「练这一句」，才进答题；
- 单句练完的结算屏也换了：一个结论（对了/错了/记成「不会」）+「回到扫读」，
  不再摆三块色块和「到期题正确率」—— 一道题的正确率没有意义。

## 三、判据

| 断言 | 拦的是什么 |
|---|---|
| 扫读点句用 `replace` | 同一页在历史里堆格子 |
| 单挑/扫读那一轮里，返回先回「怎么练」 | 返回直接把人踢出训练 |
| query 被清掉时题目复位 | 返回之后画面不变（「返回没反应」） |
| 单句练完不摆整轮统计 | 一道题也端出「正确率 / 到期题」 |
| 扫读条目带例句条数 | 浮层里说不出「N 句」 |

行为断言：`scanBatch` 的每条都带 `count`（与真实例句数一致）和 `zh`（翻译）。
