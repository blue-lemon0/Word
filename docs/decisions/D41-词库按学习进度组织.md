# D41 —— 词库按「学习进度」组织，而不是按「仓库口径」

> 决策日期：2026-10-19
> 一句话：**这一页回答的是「我现在该练什么」，不是「库里有多少 T1、多少条缺例句」。**

---

## 一、原来的分类是给内容生产看的

旧词库页的分页是：全部 / 需精修 / 缺例句 / T1 / 未掌握，列表按字母排。

这套口径对**做内容的人**有用（哪些词还没写完），但对**背单词的人**是噪音：
打开词库第一眼看到的是「899 个词缺例句」，而他真正的问题是「今天练哪几个」。
更糟的是字母序 —— 「army」永远在最前面，跟该不该复习毫无关系。

## 二、新的组织：先「今天」，再「五个桶」

**顶部一张卡**直接给答案：

```
今天有 12 个词到期
在学 48 · 待学 320 · 已掌握 156
[ 复习这 12 个 ]        ← 主按钮，点了直接开练
```

**列表按学习状态分五桶**，顺序就是人心里想事情的顺序：

| 桶 | 判据 | 桶内排序 | 能开练 |
|---|---|---|---|
| 今天到期 | `reps>0`、未掌握、`dueAt<=now` | 到期早的在前 | ✅ |
| 在学 | 练过、未掌握、**没**到期 | 字母 | ✅ |
| 待学 | 没有进度行或 `reps=0` | 字母 | ✅ |
| 已掌握 | `mastered && !rusty` | 字母 | — |
| 搁置 | `hidden`（暂时不学） | 字母 | — |

一个词有多个义项时，**这个词的桶取它最紧要的那个义项的桶**（到期 > 在学 > 待学 >
已掌握 > 搁置）。否则「army 有 2 个意思，一个到期一个没到期」就没法归类。

默认只展开前三个桶；已掌握和搁置折起来 —— 它们不该抢注意力。

## 三、桶能开练：词库从台账变成入口

每个桶的标题右边有「练这组」，点了跳 `/train?scope=due|new|learning`。
训练页认这个 scope，用 `buildScopeQueue(scope)` 组队列（与桶的判据是同一套定义，
改一处必须改另一处 —— 守卫盯着这两边）。

这是这一页最重要的变化：**它不再只是「看我有什么」，而是「从这儿开始练」**。
「词库 → 看一眼 → 退出去训练」这个来回没了。

## 四、仓库口径没有删，只是降级

「需精修 / 缺例句 / T1」收进页面最下面的「维护词库（内容视角）」，默认折叠。
它们仍然有用（补内容、跑 AI 体检之前先看看哪里最薄），但那不是学习的视角。
AI 体检的入口也放在这里 —— 它同属「维护」。

## 五、判据

| 断言 | 拦的是什么 |
|---|---|
| 五个桶都在，且 `bucketOf` 与 `rank` 取最紧要的桶 | 桶漏了 / 一个词被算进两个桶 |
| 每个桶都能开练（`/train?scope=`） | 桶只是标签，点了没反应 |
| 训练页认 scope（`buildScopeQueue`） | 跳过去还是按到期组队 |
| 维护口径是可折叠的「维护」视角 | 仓库口径又爬回首屏 |

行为断言（`flow_smoke`）：没练过的进「待学」、练过未到期进「在学」、
到期进「今天到期」，且三者互斥。
