# D40 —— 整库体检：把「想起来才点一下」变成一次能跑完的维护

> 决策日期：2026-10-19
> 一句话：**逐词串行跑、逐词确认、随时能停；跑过的词结果缓存，再跑不花钱。**

---

## 一、为什么需要它

D38 之后，AI 的用法是「我在某个词上看出问题 → 点一下」。问题是：
**我没看过的词，永远不会被审查。** 词库不是一次做完的，它会长、会被导入覆盖、
会有一批批「草稿」状态的内容（D37 顺手加入的占位义项就是），
而这些东西的问题分布是均匀的 —— 只靠“想起来”等于放弃维护。

所以体检要解决的问题不是“更聪明的审查”，而是**让审查发生**：
一次动作、一个进度、一个明确的终点。

## 二、节奏：一个词一拍

```
开始 → [跑词 A] → 摆出 A 的问题 → 你点「应用」/「先不动」 → [跑词 B] → …
```

- **串行**：并发请求既容易撞限流，也让「现在第几个词」没法交代。
- **一拍一个词**：每次只摆出**当前这个词**的提议（复用 D38 的 `AiSheet`），
  用户不会面对一屏三十条建议而无从下手。
- **随时能停**：这是一次花钱的动作，停止按钮常驻在顶栏。
- **停不丢进度**：体检不存档，因为**进度就是缓存** ——
  跑过的词结果按内容指纹存在 `aiCache` 里，再进来是 0 token（界面会写“缓存”）。

## 三、先跑哪个：把预算花在刀刃上

排序（`ai/audit.ts`）：**需精修 > 缺音标 > 例句少 > 其它**。

理由：体检一次要 N 次调用（N = 词数）。先跑的必须是最像有问题的：
- 需精修 = 明确标记为“草稿”的义项；
- 缺音标 = 有新词进来（D37 顺手加入的词就没有音标）；
- 例句少 = 内容最薄，AI 的补充收益最大。

## 四、体检一并覆盖的两类提议

| 类型 | 提案 | 为什么放在审查里 |
|---|---|---|
| 音标 | `word.update` | 音标属于词条，不属于义项；缺失是最常见的“半成品”信号 |
| 熟词僻义 | `sense.update` 的 `trap` | 判断“这个词日常最熟的意思是不是别的”需要看全词，单看一条义项判不了 |

**TRAP 必须由人确认**，因为它不只是显示标记：它会把新卡的起始间隔压到最短
（`docs/design/03`）。自动标错 = 复习计划被悄悄改错，而且不会报错。
体检把它摆出来、由人点，是这条风险的唯一解。

### 两条从真机输出里收紧的规则

1. **音标只补缺，不改写**。第一次体检跑完发现 AI 把一个对的 `/ˈæspɛkt/`
   改成了 `/æspekt/` —— 音素没错，但**重音丢了**。模型判断“音标对不对”并不可靠，
   而重音符号对学习是有用信息：缺音标时补上是纯收益，已有音标时改写是纯风险。
   所以 `parse.ts` 里已有音标就丢掉这条提案（并在 note 里说清“只补缺”）。
2. **`note` 只收“给学习者的辨析线索”**。真机上见过 AI 把
   「保留语法义，但例句要换；另补“外观、样子”义」写进 note ——
   那是给我们的操作建议，进了 note 就变成用户看到的那行提示，既不像释义也不像提示。
   现在含「例句 / 义项 / 建议 / 补 / 换掉」这类内部说法的 note 一律丢弃。

## 五、花费

一次全库 ≈ 1k tokens/词。18 个词的小库 ≈ 18k tokens（几分钱）；
正式库 2998 词也就 3M 量级，且**只跑一次**（之后靠缓存 + 只跑变过的）。
界面上会显示每个词用了多少 tokens，跑完给总数。

上下文还做了两处截断：每个义项只带**头两句**例句（一个词四个义项二十句，
光输入就两三千 token），并明确告诉模型“另外还有 N 句没列出来”——
否则它会以为“就这几句”，据此提的建议就是错的。
提示词另有一个 `PROMPT_VERSION` 进缓存键：改 prompt 形状时可以整体作废旧缓存，
不用靠“内容刚好变了”去碰运气。

## 六、判据

机械断言：

| 断言 | 拦的是什么 |
|---|---|
| 体检是二级页（`/audit` 没有 `meta.tab`，从「更多」进） | 又一个 tab：维护动作占了「地方」 |
| 串行跑词、只提议不自动应用 | `audit.ts` 里出现 `applyAll` |
| 随时能停，停下不丢已跑的结果 | 停按钮没了，或停止后清空缓存 |
| 按「最可能需要修」排序 | 排序退回字典序，等于先花钱看没问题的词 |
| 能提出音标与熟词僻义 | 两类半成品永远修不到 |

行为断言（`flow_smoke`）：需精修的词排第一、体检对象带 `refine/hasIpa` 判据、
只列有义项的词。真机：用真实 key 跑过整库一轮。
