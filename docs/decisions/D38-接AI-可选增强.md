# D38 —— 接 AI：只做一个插件，不做地基

> 决策日期：2026-10-19
> 一句话：**AI 是可选增强**；代码全部在 `src/ai/`；它只产出**提案**，
> 落库永远由人点一下。
> 目的只有两个：方便、能省则省。

---

## 一、边界：AI 不能写库

这是整件事里最要紧的一条。

| | 谁做 | 走什么 |
|---|---|---|
| 判断「哪里该改」 | AI | 一次请求，出一张提案列表 |
| 决定「改不改」 | 人 | 浮层里逐条看，可单条忽略 |
| 真正改库 | 人点「应用」 | `ai/apply.ts` → 已有的 `edit.*` 原语 |

`ai/apply.ts` 用的全是手点界面用的那几个函数（`updateSense` / `addSentence` /
`replaceSentence` / `addSense`），所以 **AI 改内容的能力不超过手点能做的范围** ——
出问题时，用户手改一次就覆盖掉了。批量应用前自动存一张内容层快照
（`snapshot('AI 应用前')`）：AI 一次改五条，人不可能逐条回滚。

写库的代码里没有一处 `db.senses.put/update`（守卫盯着），
这件事不该靠自觉。

## 二、协议：OpenAI 兼容，不绑定 DeepSeek

接的是 `/chat/completions` + `Authorization: Bearer`，也就是 OpenAI 兼容接口。
DeepSeek 只是默认值，出现在**一个地方**（`ai/config.ts` 的 `DEFAULT_CONFIG`），
代码里没有任何 `if (provider === 'deepseek')`。换供应商 = 改地址 + 模型名。

- 默认模型 `deepseek-chat`（便宜档）。要更强的效果自己改配置，不用改代码。
- 要求 `response_format: {type:'json_object'}`；被网关拒了（400 且提到该字段）
  会自动去掉这个字段重试一次 —— 否则「换了个网关整个功能不能用」，
  而错误只会告诉你 400。

## 三、传输：三条路，能力最强的先用

**WebView 里 `fetch` 打第三方接口会被 CORS 拦**：对方不返回
`Access-Control-Allow-Origin` 时，浏览器连请求都不发，页面只看到
「Failed to fetch」。所以：

| 场景 | 走哪条 | 为什么 |
|---|---|---|
| APK（手机） | 原生桥 `NativeBridge.httpPost` | 原生没有 CORS 这回事 |
| 桌面 `npm run dev` | vite 的 `/ai` 代理 | 同源转发，绕开 CORS |
| 允许跨域的网关 | 直接 `fetch` | 兜底 |

`@JavascriptInterface` 只能同步返回基本类型，所以原生这条路是
「起线程 → 拿到结果 → `evaluateJavascript` 回调 `window.__wbHttp(id, status, text)`」，
页面侧用 id 把 Promise 接回去（`ai/transport.ts`）。超时两边都有
（页面 90s、原生读 120s）：模型慢不该表现成「卡死」。

## 四、省钱：四个闸门

1. **一次请求看整词**：审查时该词的义项与例句一次带上，而不是「每个义项问一次」。
   「补一句 / 换一句」只带那个义项和它已有的句子，多带就是多花钱。
2. **硬上限**：`max_tokens` 1400、`temperature` 0.2、例句 12-20 词；
   整词审查最多 12 条提案（多句同错时优先逐句替换，不要为压条数只改一句）
   —— 约束写在 prompt 里，比任何参数调优都省。
3. **结果缓存**（Dexie `aiCache`）：键含**内容指纹 + 模型名**。内容没变就
   永远不再花钱；内容一改键就变，不会拿旧建议去改新内容（那比没缓存更危险）。
   命中缓存的界面上会写「这次没花钱」。
4. **不自动调用**：所有 AI 动作都由人点。开一个词条页不会偷偷花掉一次调用。

## 五、界面：多个入口，一个浮层

| 位置 | 动作 | 产出 |
|---|---|---|
| 词条页顶栏「AI 审查」 | 整词审查（义项与例句的错、缺、重复） | 提案列表 |
| 词条页顶栏「AI 补全」 | **空壳词**补齐：义项 + 每义项 2 句例句 | 提案列表 |
| 意思页「AI 审查」 | 只审这个意思，**带全它的例句**；可附一句临时补充要求 | 提案列表（可多条替换） |
| 意思页每句「AI 换一句」 | 换掉这一句，保留它要教的义项 | 1 条替换提案 |
| 意思页底部「让 AI 补 3 条候选例句」 | 补几句新的 | 3 条新增提案 |
| 更多页「AI 助手」 | 配置地址/模型/Key、测试连接、清缓存 | — |

> 2026-10-30 补记：整词审查为了省 token 每义项只带前 2 句，多句犯同一个错时
> AI 看不到后面的句子，只能补一句新的。意思页的「AI 审查」改为带全该义项例句，
> 并要求「多句同错就逐句替换」；换句动作也保证目标句一定在上下文里。
> 补句/换句的上下文现在会单独标出【当前义项】，默认提示词也要求锁定它：
> 义项较生僻时宁可句子简单，也不要退回该词更常见的意思，更不要把其它义项的
> 常见搭配套过来。备注只是一个可选单行输入，只影响这一次请求，不做聊天/历史。

「审查」与「补全」**按词的胖瘦分流**：没有释义（或只有占位义项）走补全，
有正经释义走审查 —— 对已经有主的内容做「补全」，等于让 AI 重写它。

「补全」也是 D37 那个「顺手加入词库」的收尾：从训练页点开一个生词 →
加入词库（占位义项）→ 浮层按钮变成「让 AI 补全义项与例句」→
跳到词条页时带 `?fill=1`，那边**当场**开始补（不再让你找一个刚看过一次的按钮）。

新义项没有 id / slot，占位义项则要替换旧句，所以例句只能**跟义项一起提**
（`sense.add` / `sense.update` 都带 `sentences[]`），落库时才挂得上去 ——
分成两条提案的话，parse 绑不到 slot，例句会被静默丢掉。浮层里也会**把这几句
直接摆出来**（句子是最后要背的东西，只写「＋2 句」等于让人盲签）。

> 2026-10-21 补记：补全改为每个义项固定 2 句，且整份提案**全有或全无**——
> 任一义项没凑够就整份拒绝，不再接受「有的义项有句、有的没有」。占位义项
> 走 `sense.update` 时也在同一条提案里带 `sentences[]`。

「补全」在应用时会顺手摘掉那个义项的 `needsRefine` 标记：它原本的意思是
「占位义项待补」，补完了还挂着，词库的「需精修」筛选就成了噪音。

所有动作产出的是**同一种东西**（提案列表），所以只有一张浮层
（`AiSheet.vue`）：逐条看「改后是什么、为什么要改」，可单条忽略，
也可以「只应用这条」。配置没填时入口**不出现**（而不是点进去才说「请先配置」）。

### 配 Key 的两个细节（都是真实踩出来的）

1. **填了 Key 就顺手把开关打开**：真实的失败是「key 填好了、点保存、
   回词条页 —— 按钮不出现」，因为那个「开关」只是右上角一个小圆点。
2. **「已保存 Key，但开关是关着的」要在设置页里显式写出来**：
   否则页面上看不出 AI 没开，只会觉得「功能没生效」。
3. 入口的可见性用**共享的 `aiReady`**（`ai/config.ts`），不是各页面自己算 ——
   配置在「更多」页改，入口在词条页/意思页，各算一次就会「配置完回来看不到」。

## 六、安全：Key 只在这台设备上

- 存 `localStorage`，**不进备份**：备份是会发给别人、会过微信的文件，
  把 key 塞进去等于每次导出都在复制密钥。
- 界面只显示遮起来的版本（`sk-ab••••wxyz`），输入框留空表示「不改」。
- 「测试连接」是一次 8 token 的 ping：最贵的错是「配错了 key，
  等真正用 AI 时才发现」。

## 七、以后要加新动作

在 `ai/prompts.ts` 写一个 prompt 函数（返回两条 message），
在 `ai/actions.ts` 加一个四行包装（取上下文 → `run(...)`），
需要新提案类型才动 `types.ts` / `parse.ts` / `apply.ts`。
界面复用 `AiSheet` —— 这就是「不专门为某个 AI 设计」的落点：
**动作是插件，流水线是地基。**

## 八、判据

机械断言（`scripts/verify_docs.py`，10 项）：

| 断言 | 拦的是什么 |
|---|---|
| AI 代码只在 `ai/` 里 | 别处偷偷直连外网的接口 |
| AI 只提议不写库 | 某个动作里直接 `db.senses.update` |
| 建议必须绑定到真实行 | 幻觉的 slot / sentenceId 落库 |
| 缓存键含内容指纹与模型名 | 「内容改了还在用旧建议」 |
| Key 不进备份 | 备份文件里出现 `apiKey` |
| 手机端走原生网络 | 真机里 fetch 被 CORS 拦掉 |
| 没配 AI 时入口不出现 | 点进去才说要配置 |
| 改多条前先打快照 | 一批改动无法整批退回 |
| 换/手改例句必须重算高亮区间 | 高亮打在别的词上 |
| 新句子里必须真有这个词 | 漂亮但没有目标词的句子进库 |

行为断言（`app/web/tests/flow_smoke.mjs`，注入假传输跑全链路）：
没配 key 不发请求、一次审查只发一次、端点与鉴权头、幻觉被丢弃且有交代、
同样内容第二次命中缓存、应用后释义/例句/高亮区间都对、应用前有快照、
内容一改缓存失效；手改英文后按旧词形重算高亮，找不到目标词时清空而不是保留旧区间。
