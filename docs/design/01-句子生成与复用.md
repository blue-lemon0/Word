# 句子生成与复用设计

> 关联：D15（词库 7884 义项）、D13（动态生成防作弊）
> 前提：**39420 句**（7884 义项 × 5）不可能一次生成完，
> 必须有"边练边补"的增量机制。

---

## 1. 为什么不能一次性生成

| 约束 | 数值 |
| --- | --- |
| 义项总数 | 7884 |
| 每义项目标句数 | 5 |
| 总需求 | 39420 句 |
| 每句 LLM 输出 | ~120 token |
| 一次性生成成本 | ~4.7M token，且**全部要在首次使用前完成** |

用户当前禁用 LLM 通道，39420 句需要数周。**结论：必须设计成"用多少补多少"。**

---

## 2. 三层句子供给

```
┌─ Layer 1  预生成池（离线批处理）────────────────────┐
│  开发机跑批，为高频词批量生成，产出 data/sentences/ │
│  覆盖：T1 档 663 词 × 4 义项 = 2652 义项            │
│  目标：先把这 2652 个义项各配 5 句 = 13260 句        │
│  离线包 ~3MB，一并打包进 APK                        │
└─────────────────────────────────────────────────────┘
┌─ Layer 2  运行时按需生成（联网时）─────────────────┐
│  触发：该义项 active 句 < 2 时，后台异步生成         │
│  每次 1-2 句，不阻塞当前题                           │
│  产出 source=LIVE，与池句同权进入轮换                │
└─────────────────────────────────────────────────────┘
┌─ Layer 3  复用兜底（永不失败）─────────────────────┐
│  上面两层都没命中时：同义项换句 / 同词他义换句 /     │
│  全局同 gloss 换句 —— 总能找到一句能问的            │
└─────────────────────────────────────────────────────┘
```

**Layer 3 是硬保证**：无论网络、无论 LLM 状态，**永远有题可练**。
这是"离线可用"红线（规格 §11）的兜底实现。

---

## 3. 句子状态机

每条句子有独立状态，与义项状态正交：

```
   生成 ──> pending ──质检──> active ──────> retired ──> (归档)
              │                 │  ↑            │
           REJECT            bad │            │
              │                 └──┴────────────┘
           重生成(≤2)          用户标记"有毛病"
```

| 状态 | 含义 | 能否出题 |
| --- | --- | --- |
| `pending` | 已生成未质检 | 否 |
| `active` | 质检通过，在役 | **是** |
| `retired` | 已退役（见过且答对，见 §5） | 否 |
| `bad` | 判错/用户标记 | 否，等重生成 |
| `rejected` | 质检不过 | 否，重生成 |

## 4. 生成契约

### 4.1 输入

```jsonc
{
  "word": "run",
  "senseId": "s2",
  "pos": "vt.",
  "glossZh": "赛跑",
  "tier": "T1",
  "avoidSenses": ["跑", "奔跑", "奔跑的路程"],  // 同词他义，必须避开
  "avoidSentences": ["a3f1c2", "b7e9d0"],      // 指纹去重
  "difficulty": 2
}
```

`avoidSenses` 是**关键约束**：生成的句子必须能唯一确定是本义项，
不能"这句也可以理解成另一个义项"。质检器会独立验证这一点。

### 4.2 输出

```jsonc
{
  "text": "She runs a small bakery with her sister.",
  "clue": "bakery",
  "spanStart": 9,
  "spanLen": 6,
  "translation": "她和姐姐一起经营着一家小面包店。",
  "note": "run a business 是固定搭配，此处是「经营」不是「奔跑」。",
  "fingerprint": "a3f1c2",
  "source": "GENERATED",
  "promptVer": "gen-2026-09-v1"
}
```

> **`span` 定位的是 clue，不是目标词**（D15 之后的口径）。
> 目标词由句子本身决定，clue 是给用户的判别线索词。
> 当前 4 条同义改写无法字面定位，标 `SPAN_HINT` 只高亮目标词。

### 4.3 七约束（继承规格 §5.1 的四约束）

| # | 约束 | 质检判据 | 失败率预期 |
| --- | --- | --- | --- |
| G1 | 目标词存在且词形匹配 | 分词后含目标词或合法变形 | <2% |
| G2 | 句长在难度档 | D1 7-12 词 / D2 12-16 / D3 14-20 | <3% |
| G3 | 背景词不超纲 | 非目标词 ∩ CORE 3000 = ∅ | 5-10% |
| G4 | 线索词存在 | `clue` 在句中可字面定位 | <3% |
| G5 | **义项唯一性** | 独立判定"这句最可能是哪个义项" | 8-15% |
| G6 | 译文含目标义项 | 译文中出现该义项核心词 | <5% |
| G7 | 指纹不重复 | 与全库已有句子无重复 | <1% |

**G5 是新增的、也是最重要的**。旧设计没有这条，导致同一句可以
合理地理解成多个义项，判分就变成"猜出题人的想法"而非"读懂句子"。

> **质检 REJECT 率健康区间：8-20%**。低于 5% 说明质检器放水，
> 高于 25% 说明生成 prompt 与规格脱节，需要调 prompt 而非改判据。

### 4.4 质检与生成解耦

质检器 prompt **只看成品句子 + 义项定义**，绝不看生成过程。
否则两个判断共享同一错误假设（P0-1 的根因）。

```
生成器：  "请为 run#s2（赛跑）写 5 个句子"
质检器：  "句子 X 中 run 最可能是什么意思？选项：跑/赛跑/奔跑的路程。只输出选项号。"
```

第二个 prompt 不告诉质检器这句话是谁生成的。

> **G5 的实现受通道状态约束。**
>
> | 场景 | 判定方式 | 理由 |
> | --- | --- | --- |
> | **实时生成（App 内）** | 规则判定：译文核心词匹配 + 同词他义排除法 | 当前无 LLM 通道；且实时路径不能依赖第二次 LLM 调用（延迟与成本） |
> | **离线批量预生成** | 独立 LLM 判定 | 质量优先，成本可摊薄，延迟不敏感 |
>
> 规则版 G5 只能做到"排除明显歧义"，做不到"确认唯一"。
> 因此**实时生成的句子默认进 `pending`，需离线批量质检后才转 `active`**——
> 这也符合 §3 状态机里"生成与质检解耦"的初衷。

## 5. 复用规则

### 5.1 句子指纹

```
fingerprint = sha1(归一化(小写化(去标点的 text)))[:6]
```

用于全库去重。同一句文本只允许存在一次（跨词、跨义项）。

### 5.2 选句优先级

给定一个义项要出题，按顺序取：

1. `active` 且 `seenCount = 0`（**没出过的优先**）
2. `active` 且 `lastShown` 最久远
3. `active` 且 `seenCount` 最少
4. `source=LIVE` 优先于 `GENERATED`（新生成的更贴合当前难度）
5. 都不满足 → 触发 Layer 2 生成

**绝不连续出同一句**。同一义项两次出现之间至少隔 2 个其他义项。

### 5.3 句子轮换阈值

| 条件 | 动作 |
| --- | --- |
| 同一句**连续**答对 3 次 | `active → retired` |
| 同一句答错 1 次 | `seenCount` 归零，`lastShown` 清空 |
| 用户点"这题有毛病" | `active → bad`，立即生成替换句 |
| `retired` 数 ≥ 3 | 从库中物理删除（归档到 `retired.jsonl`） |
| `retired` 数 < 3 | 保留，作为"几乎掌握"的证据 |

> **为什么是"连续 3 次"而不是"累计 3 次"**：
> 累计会把间隔复习的正确答案也算进去，导致句子过早退役，
> 而复习正是最需要这句的场合。连续答对才说明"这句话已经会了"。

### 5.4 跨义项复用（Layer 3）

| 情况 | 降级策略 |
| --- | --- |
| 本义项无 active 句 | 用**同词他义**的句子，但把题干改为"选出**不是**该义项的句子"（反向题） |
| 同词也无 | 用**近义词**（同 glossZh 或同 pos）的句子，反向题 |
| 全局都无 | 用该词任一 `bad` 句 + 题干加"（此题有争议）"提示 |
| **该词一条句都没有** | 无句状态：显示词/词性/释义 + "这个义项还没有例句"，不出题 |

反向题让句子 100% 可复用，是 Layer 3 能"永不失败"的关键。

> **复用的边界（D16）**：以上全部发生在**新词库内部**。
> 旧库的 18201 条句子已删除且不迁移——它们的 `senseId` 已全部失效。
>
> 最后一行"无句状态"是 D16 之后当前的常态：7884 个义项全都没有句子。
> `tools/index.html` 已实现该状态，`scripts/e2e_d16.js` 24 项测试覆盖。

## 6. 增量生成调度

### 6.1 预取（Prefetch）

会话开始时，一次性算出本次会话涉及的义项并检查水位：

```
for 每个待练义项:
    if activeCount < 2:  标为 NEED
    if activeCount == 2: 标为 SOON     # 刚好够用，下次再来就危险
会话结束前：
    对所有 NEED 义项，排队生成 2 句
    对所有 SOON 义项，排队生成 1 句
```

**阈值 2 的理由**：一个义项平均每 5 场会话出现 1 次，
若只剩 2 句时开始补，每次补 2 句就能维持平衡。

### 6.2 速率限制

| 项 | 值 | 理由 |
| --- | --- | --- |
| 每分钟最多请求 | 8 次 | 不触发服务端限流；成本可控 |
| 单次生成句数 | 2 | 减少单点失败损失 |
| 失败重试 | 1 次，间隔 30s | 失败多为网络抖动 |
| 连续失败 3 句 | 停止该义项生成，转 Layer 3 | 不拖累整场会话 |

### 6.3 上限

| 项 | 值 |
| --- | --- |
| 每义项 active 句上限 | 30（硬上限，到顶不再生成） |
| 触发上限后 | 转为"只退役不补充"模式 |
| 全库 active 句上限 | 236520（7884×30），实际靠退役自然收敛 |

## 7. 质量指标

| 指标 | 目标 | 含义 |
| --- | --- | --- |
| REJECT 率 | 8-20% | 质检器是否在干活 |
| G5 失败率 | 8-15% | 义项唯一性——最难也最关键 |
| 用户"有毛病"标记率 | < 0.5% | 真实用户比 LLM 质检更准 |
| 句子复用率 | < 30% | 若过高说明生成跟不上，Layer 3 在兜底 |
| Layer 3 触发率 | < 10% | 同上 |

## 8. 待定

1. **LLM 通道何时解封**。当前禁用，Layer 2 完全跑不起来，
   只剩 Layer 1（预生成）+ Layer 3（复用）。恢复后需先做 2652 个 T1 义项。
2. **G5 判定的准确率**。用 LLM 判"最可能是哪个义项"，
   本身也可能有偏。需实测：对同一批句子，
   LLM 判定与人工判定的吻合率应 > 90%，否则需要换判定方式。
3. **反向题是否需要单独标记**。它改变了任务形态（选"不是"），
   可能干扰判别训练主线。倾向：反向题只在 Layer 3 兜底时出现，
   且不计入正确率统计。
