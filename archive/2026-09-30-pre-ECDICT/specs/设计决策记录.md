# 设计决策记录 · 问题与对策

> 这不是规格文档，是**问题台账**。每条记录一个"发现的问题 → 根因 → 会带来什么 → 对策 → 怎么验证"。
> 规格文档描述"应该做成什么样"，本文件记录"为什么是这样，以及曾经错在哪"。
> 记录方式遵循本项目哲学：**改动自然语言比改动代码容易**。因此每条对策都必须落到"可读的文本资产"上，而不是需要改代码的硬编码逻辑。

## 0. 阅读约定

| 字段 | 含义 |
| --- | --- |
| **问题** | 观察到的失效现象 |

# 第一部分：P0

## P0-1 AI 生成句子的方差，无法被训练算法吸收

### 问题

大模型生成的例句不稳定。同一个义项连生成 5 句，质量差异明显：有的句子根本不含目标义项（歧义/用错义项），有的翻译不准，有的干扰项一眼就能排除。

### 根因

**不是"AI 不够强"，而是"无约束生成的方差，超出了 SRS 算法能容忍的范围"。**

我们 v2.2 §6.3 的间隔算法是 `interval × 2.2`、`ease + 0.05`。这类算法**放大信号**。但它的输入是判定结果，而判定结果本身有噪声：

```
真实掌握度        判定结果（含噪声）
  50%        ──▶   CORRECT / WRONG 各 50%，且混入 10% PENDING、5% INVALID
```

SRS 忠实地放大这个噪声。经过 10 天，`interval` 反映的是**随机游走**，不是记忆强度。用户第 3 周开始会遇到"明明练过的词又错，明明没练的词没错"，对产品的信任崩塌。

更糟的是：**误差是不可见的**。用户不知道自己答错的那道题，题目本身是有歧义的。他只会认为是自己不行。

### 带来什么

1. **训练信号被稀释**。名义正确率 70% 里，可能只有 55% 反映真实能力，且用户无从分辨。
2. **留存杀手**。第 2–3 周出现"练了没用"的感觉，用户流失，且不会告诉我们原因（他们只会说"不好用"）。
3. **质检不可行**。v2.2 §13.4 定了"单卡生成成功率 >90%"，但**闸门（G1–G7）全部由生成层自己执行**。同一个模型既出题又判卷，错误高度相关。自检自评发现不了自己的系统性偏差——这是 LLM 评估的根本局限，不是 prompt 能修的。
4. **规模化即崩溃**。14000 个义项 × 5 句 = 7 万句。5% 错误 = 3500 句有问题的训练材料，均匀撒在 5500 个词里，每个词都有若干道题是错的。用户会在**不同时刻**遇到不同批次的坏题，故障现象随机、无法复现、无法定位。

### 对策

**核心原则：把方差从"生成"移到"筛选"。**

生成可以大胆——量大、随机、快。但必须有一个**独立于生成器**的严格筛选器。筛选器可以慢（离线批处理，不在用户路径上），可以贵，可以带人工，但**不能依赖生成器自己的判断**。

三层叠加，逐层消灭一种方差：

| 层 | 手段 | 消灭的方差 | 成本 |
| --- | --- | --- | --- |
| L1 语料真实化 | 句子骨架来自**考研真题**，不用凭空生成 | 自然度、歧义、使用正确性 → 归零 | 需建设真题切片管线 |
| L2 AI 只做减法 | AI 只做拆句、简化、删修饰，**不写新句子** | 语义漂移 → 极小 | 便宜 |
| L3 独立质检 | 另一次独立的 AI 调用，输入包含句子+目标义项+干扰项，输出"这题有效吗"，**不看生成过程**；关键批次叠加人工抽检 | 判别有效性 → 归零 | 2× token |

L1 是最重要的一层。**让 AI 做题，比让 AI 出题，可靠一个数量级。**

L3 的关键设计：**质检器的 prompt 与生成器完全解耦**。质检器看到的只有"成品"和"规格"，不看到"怎么生成的"。这是交叉验证的最低要求。若质检器也看推理过程，两个判断会共享同一个错误假设，等于没检。

**推论：v2.2 §8.3 的 7 道闸门全部作废，替换为 L3 独立质检。** 规则闸门（G1 词形匹配、G2 句长）保留，但降级为"廉价预筛"，不能作为质量保证。

### 落点

- `assets/pipelines/sentence_pipeline.md` — 流水线定义（切片→筛词→拆句→质检→入库），纯文本配置
- `assets/prompts/generator.md` / `assets/prompts/judge.md` — **两个独立 prompt 文件，带版本号**
- `assets/corpus/kaoyan/` — 真题切片（原文版权存疑，见 P0-5）
- CI 校验：质检未通过的句子不得进 `GeneratedSentence` 表

### 验证

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 质检不通过率 | < 5% | **不通过是好事**，说明质检器在干活。接近 0% 说明质检器形同虚设 |
| 人工抽检与质检结论一致率 | > 85% | 低于此说明质检器不可信 |
| 用户报告"这题有歧义" | 每周 < 3 例 | 需提供反馈入口（见 P1-9） |
| 同一义项不同句之间质量方差 | 可观测、可度量 | 目前**不可度量**，需补 |

## P0-2 没有考试日期，产品就没有推进引擎

### 问题

v2.2 全文没有出现"考试日期"。产品不知道自己离考研还有多久。

### 根因

v2.1/v2.2 是按"通用英语学习者"设计的——所以需要 §5.2 冷启动自测去**猜**用户水平。但**考研用户不存在水平不确定性**：他要么在考研，要么不在。水平规格就是考研大纲本身。

**我们在给一个已知答案的问题做估计。** 这是 v2.1 双轨画像在考研场景下的退化。

### 带来什么

1. **训练材料无法排优先级**。5500 词平铺，用户不知道先学哪个。真实的考研节奏是分阶段的（基础 → 强化 → 冲刺），平铺等于放弃了这个信息。
2. **会话长度无法自适应**。冲刺期用户要量，基础期用户要轻。固定 12 题两头不讨好。
3. **没有情绪引擎**。这是最致命的。判断"今天值不值得学 12 分钟"，用户脑子里只有一个问题："离考试还有多久？" 我们的首页必须能秒答这个问题，否则用户每次都要自己去查。
4. **留存缺少外部锚点**。没有倒计时，产品的"连续天数"就只是一个游戏化数字。倒计时是真实力。

### 对策

**一、首次启动时必须问一次考试日期，且允许"未确定"。**

日期决定三件事，全部本地计算，不需服务器：
- 阶段划分（见下表）
- 目标词书
- 每日建议量

**二、阶段划分**（以 12 月倒数备考为例，实际按剩余天数反推）

| 阶段 | 剩余时间 | 目标 | 训练侧重 |
| --- | --- | --- | --- |
| 基础期 | > 6 个月 | 大纲核心词全覆盖 | 新义项为主，句子难度 D1–D2 |
| 强化期 | 3–6 个月 | 覆盖大纲全量 | 真题词优先，句子难度 D2 |
| 冲刺期 | < 3 个月 | 高频 + 错词 + 作文词 | 复习为主，句子难度 D2–D3 |

阶段**自动切换**（按剩余天数），也可手动锁定。切换时明确告知，不静默改变。

**三、取消冷启动自测。**

- 无日期的用户 → 才走 3 题自测
- 有日期的用户 → 直接按阶段开训，画像 = 阶段 + 大纲
- 这直接删掉了 v2.2 §5.2 的一整套设计，也删掉了"猜不准"的长期风险

**四、首页第一元素是倒计时 + 今日目标，不是训练入口。**

### 落点

- `assets/profiles/kaoyan_stages.md` — 阶段定义、剩余天数映射、每日建议量，全部可读可改
- 用户设置项 `examDate`（可为 null）

### 验证

| 指标 | 目标 |
| --- | --- |
| 设置了考试日期的启动用户占比 | > 85%（"未确定"应是小众选项） |
| 启动到首次训练的转化率 | > 60%（当前设计预计 < 40%，因需先过自测） |

## P0-3 词库是"发版资源"，所以"难改造"

### 问题

用户反馈"找不到词库""难以改造词库"。v2.2 把 `Word` / `Sense` 定义成了运行时数据表，隐含假设是词库随 App 发布。

### 根因

**词库变更需要发版，就是"难改造"的全部原因。**

考研用户对词库的需求高度个性化且高频变动：换词书（红宝书 / 恋练有词 / 墨墨 / 自己整理的）、只练真题高频词、按大纲词表增删。这些在"发版资源"模型下，全部要走"改数据 → 打包 → 发版 → 等审核 → 用户更新"。没有用户会为改一份词表等两周。

而且 v2.2 完全没有设计**词库导入**。用户自己的词书进不来，只能用内置的。

### 带来什么

1. **用户被锁死在官方词库**。用自己词书的用户（备考人群的多数）直接流失。
2. **内容更新滞后**。大纲换版、真题年度更新、词表修正，全部被发版节奏拖死。
3. **运营失去迭代能力**。发现一批难例句想下架，只能等发版。
4. **与项目哲学直接冲突**。"改动自然语言比改动代码容易"——词库是最大的自然语言资产，却做成了要发版的代码资产。**这是本项目最讽刺的一处设计失误。**

### 对策

**把一切内容变成 repo 内的文本资产，走热更新下发。**

```
assets/
  wordlists/
    kaoyan_dagang_5500.tsv      # 大纲词表，TSV：lemma \t pos \t 义项1 \t 义项2 ...
    kaoyan_core_2500.tsv
    kaoyan_essay_800.tsv        # 作文高频
    _user_import.tsv            # 用户导入，格式同上，可空
  sentences/
    w_run#v1.jsonl              # 每义项的例句，含 provenance
  prompts/
    generator.md  judge.md  extract_senses.md
  profiles/
    kaoyan_stages.md
```

发布流程：

```
TSV 改动（自然语言）
  → CI：schema 校验 + 词表去重 + 义项合法性 + 例句覆盖率检查
  → 签名，产出 assets.bundle
  → 上传 CDN
  → App 启动时检查版本，有新版则静默下载
```

**用户导入词书**支持四种来源，全部本地解析：粘贴文本、上传文件、拍照 OCR、从其他 App 导出。解析后**必须让用户确认义项切分**——这是唯一需要人工介入的环节，因为 AI 切错义项会毁掉整个词的训练（见 P2-1）。

**词书切换 ≠ 重置进度。** 换词书只是换训练池，已练过的义项记录（`SenseSrsState`）按 `lemma + senseId` 保留。

**例句的 provenance 必须记录**：

```jsonc
{
  "text": "...",
  "source": "KAOYAN_2019_TEXT2_S3",       // 来源可追溯
  "transform": "SPLIT+SIMPLIFY",           // AI 做了什么
  "judgeVer": "judge-2026-03-v1",          // 哪个质检器版本放行的
  "generatedAt": "2026-03-11"
}
```

出问题时能精确回答"这道题为什么长这样"，并且可以只重做这一条。

### 落点

全部落点即上述 `assets/` 目录结构本身——这是本项目最重要的工程决策。

### 验证

| 指标 | 目标 |
| --- | --- |
| 词库内容更新到用户可见的时延 | < 24h（从提交到生效） |
| 用户导入词书的成功解析率 | > 80% |
| 使用自己导入词书的用户占比 | > 40% |

## P0-4 无账号 + 进度可读导出，换手机不丢

### 问题

"记不住用户进度"。这句话有两种读法，技术层面和行为层面都要解：
- **技术读法**：App 被杀、闪退、清缓存 → 进度没了
- **行为读法**：用户不知道自己能记住什么，每天从零开始的感觉

技术读法 v2.2 §13 已经覆盖（每题落库、幂等提交）。**行为读法完全没有覆盖，而且更重要。**

### 根因

行为读法的根因是：**间隔重复的价值是"时间上的记忆保持"，而这个价值恰好是不可见的。**

用户练了 3 周，体感是"我好像会一点了"，但他无法确认。真正能打消这个不确定性的，是一条数据：**"你 3 周前学的 412 个义项，现在还能答对 84%。"**

没有这条数据，用户每天都在重新建立信心，而不是积累信心。第 2 周他就放弃去查词典了——因为查一下就能确认自己会了，而查词典正是我们要消灭的习惯。

第二个根因：**无账号。** 备考人群对注册新 App 有明确抵触（要手机号、要邮箱、不知道要多久）。而如果必须注册才用，多数人直接不装。**必须无需账号可用。** 但这意味着换手机 = 丢进度，考研用户换手机是常事。

### 带来什么

1. **价值不可见 → 留存崩塌**。用户无法区分"我在进步"和"我在原地"，两者体感相同。
2. **注册漏斗杀死安装量**。需要注册才能用 → 大量流失在第一步。
3. **换手机即全部归零**。对一个备考周期长达一年的产品，这是灾难级体验。用户的应对方式会是"不敢用这个 App 记录真正的进度"，转而回到纸书。
4. **数据不可导出 → 用户被绑架**。用户不敢投入，因为无法带走。

### 对策

**一、留存曲线作为第一等公民指标。**

```
你 3 周前学的 412 个义项，现在还能答对 84%。
[ 查看曲线 ]
```

- 每个义项首次训练时记录 `firstTrainedAt`
- 之后每次复习记录 `reviewedAt + outcome`
- 曲线 = 按首次训练周分桶的累计正确率
- 计算只在**到期复习**时进行（提前复习不算），否则会被"练得多"污染

这条曲线要放在**进度页首屏**，不是深处。它是这个产品对"我到底学会了多少"给出的唯一诚实答案。

**二、默认无账号，进度全本地。**

- 不注册、不登录、不联网即可完整使用
- 设置内提供"云同步"，用户主动开启
- 开启时**不强制手机号**，允许任意账号或仅设备间同步码

**三、进度可读文本导出/导入。**

这是"改自然语言比改代码容易"在数据层的直接应用。备份不是二进制、不是加密 blob，是**一段人类可读的文本**：

```
# 考研背单词 · 进度备份
# 版本 1  导出时间 2026-03-11T20:14  剩余 245 天
# 直接粘贴导入即可恢复；可自行编辑

[词书] kaoyan_dagang_5500.tsv
[阶段] 基础期

[义项状态]  word:interval:ease:mastery
run#v1:3:2.05:MASTERED
run#v2:1:1.80:LEARNING
address#v1:0:2.00:LEARNING

[生词库] lemma:state:markedAt
bakery:FLAGGED:2026-03-10
oven:REINFORCING:2026-03-10
```

**为什么用文本而不是 JSON / 加密包**：
- 用户能看懂，出问题能自己改（P0-3 哲学的延伸）
- 跨版本兼容只需解析器容忍未知行，不需迁移逻辑
- 遇到"我进度没回来"的客服问题，用户可以直接把这段贴过来

支持"仅导出生词库 + 仅导出义项状态"的选择——多数人只想要其中一个。

### 落点

- 导出格式规范：`assets/backup/progress_format.md`（含版本号与兼容规则）
- 备份/恢复是纯文本的，代码只做解析与序列化

### 验证

| 指标 | 目标 |
| --- | --- |
| 首次启动无需注册的完成率 | 100% |
| 导出→清数据→导入 恢复成功率 | 100%（自动化测试覆盖） |
| 进度页首屏展示留存曲线 | 是 |
| 开启云同步的用户占比 | 可观测（低不代表失败） |

# 第二部分：P1（决定能不能用满 7 天）

## P1-1 约束 3 只管了"句子新"，没管"任务形态新"

### 问题

约束 3（新颖情况）要求"同一义项的例句素材不重复同源"，这只保证了**句子**不重复。但每天的训练**交互形态完全一样**：看句 → 点选项 → 看讲解。

### 根因

我们把"新鲜"理解成了素材层面的。但用户每天重复的是**动作**，不是句子。一道题换十个句子，动作还是那一个。

更具体的问题在 v2.2 §6.2：**组内 3 题是同一义项的 3 个不同句**。这在教学上正确（检验迁移），但在体验上是连续三次几乎相同的事。第 1 天觉得"哦，原来要这样判"，第 5 天就是"能不能换个玩法"。

### 带来什么

1. **第 4–7 天的新鲜感衰减**，与内容质量无关，纯粹是交互重复。
2. 组内第 2、3 题的边际价值低于第 1 题，但用户体感是"3 道一样的题"，产生"练量虚高"的错觉。
3. 达不到 v2.1 §7"只涨熟练不涨通用"的防线目标——因为练法本身就没变化。

### 对策

**引入同义项的多种任务形态，按义项轮换。** 关键约束：**同一义项的多种形态共用同一批例句与干扰项数据**，不增加内容生产成本。

| 形态 | 问法 | 数据来源 | 教学作用 |
| --- | --- | --- | --- |
| M1 多选（默认） | 此句中该词最接近哪个义项？ | 义项集 + 干扰项 | 基础判别 |
| **M2 二义辨析** | 此句中的 *run* 是"奔跑"还是"经营"？ | 同一词的 2 个义项 | **直击一词多义，考研主战场** |
| M3 判断 | 此句中该词是"经营"的意思吗？ | 单义项 | 快速复核（限制在已练 2 次以上） |
| M4 句中定位 | 选出句中与"经营"意思相符的词 | 例句本身 | 强化"词义由上下文决定" |

M2 优先级最高。**理由**：考研词汇的本质是熟词僻义，而 M2 正是"同形不同义"的直接训练。这是本产品相对背单词软件最不可替代的能力，却没有被单独设计出来。

排布规则：一个训练卡首次出场用 M1，复习时按 `M1 → M2 → M3` 轮换，M4 低频穿插（每 5 组最多 1 次）。

### 落点

`assets/rules/question_forms.md` — 形态定义 + 轮换规则，纯文本

### 验证

| 指标 | 目标 |
| --- | --- |
| 第 7 天留存 | > 25% |
| 单会话内使用到 ≥2 种形态的比例 | > 60% |
| M2 形态的正确率 vs M1 | M2 应显著更低（低 10pt 以上）。若相近，说明 M2 没起到辨析作用 |

## P1-2 用超时做主路径，会误伤认真思考的人

### 问题

v2.2 §9.2 把"25 秒超时"作为没把握的主路径，"不会"按钮作为次要路径。

### 根因

**把"系统觉得久"当成了"用户不会"。** 但 D3 难度的题需要读完 14–20 词的句子再回忆义项，25 秒对认真用户是**正常耗时**，不是卡顿。

超时还制造了一个隐蔽的伤害：**PENDING 会触发降级**（v2.2 §9.3，连续 2 题就降档）。认真思考的用户会因此不断被"降难度"，最终系统认为他很弱，一直给简单内容。而他实际上能应付更难的内容，只是慢。

**慢 ≠ 弱。** 这是个能力判断错误。

### 带来什么

1. **认真用户被持续降级**，画像失真，训练内容长期偏简单，上限被锁死。
2. 慢速用户产生挫败：明明会，却不断收到"这道题对你有点难"的暗示。
3. PENDING 率这个健康指标（v2.2 §13.4 定在 15–30%）会被污染——它测到的不是难度失配，是**阅读速度差异**。

### 对策

**反转主次：以用户主动的「不会」为主路径，超时降级为可关闭的兜底。**

| 机制 | v2.2 | v2.3 |
| --- | --- | --- |
| 主路径 | 25s 超时 | **点「不会」** |
| 超时 | 强制触发讲解+重做 | **仅高亮「不会」按钮**，不强制 |
| 触发降级 | 连续 2 题 PENDING | 连续 2 题**主动点不会** |
| 默认 | 开启 | **关闭**（设置内可开） |

**并且**：超时时长按难度档分别设置（D1 20s / D2 30s / D3 45s），而非统一 25s。即便开启，也不应跨档位一刀切。

降级触发只看**主动信号**（点不会），不看时间信号。理由：主动信号准确，被动信号有系统性偏差。

### 落点

`assets/rules/timeout_policy.md`

### 验证

| 指标 | 目标 |
| --- | --- |
| PENDING 率（仅计主动） | 15%–30% |
| 超时开启率 | < 20%（应多数用户关闭） |
| 关闭超时用户的画像降级次数 | 应显著低于开启者。若相近，说明降级逻辑本身有问题 |

## P1-3 首次会话 12 题，会劝退大部分人

### 问题

v2.2 §6.2 定了所有会话统一 12 题。首次使用也 12 题。

### 根因

12 题 ≈ 12–14 分钟。首屏就要用户承诺 12 分钟——**在用户还不相信这个 App 的时候**。

更根本的问题：首会话的目标不是"练量"，是**让用户走完一次完整闭环**，看到"我标记的词真的进了生词库""我答错的题真的有讲解"。这个闭环 5 题就能完成。12 题里后 7 题的边际价值接近零。

### 带来什么

1. **首会话中途流失**，且流失点无法观测（用户直接关掉，不报错）。
2. 第一次体验就是"很累"，后续所有会话的预期都被这 12 分钟污染。
3. 7 天留存的天花板被首会话体验锁死。

### 对策

**会话长度随账号年龄增长，且默认值可被用户改。**

| 阶段 | 建议题量 | 目标 |
| --- | --- | --- |
| 首次会话 | **5 题** | 走完闭环，建立信任 |
| 第 2–3 天 | 8 题 | 养成习惯 |
| 第 4 天起 | 12 题（冲刺期 20 题） | 形成稳定节奏 |

附加机制：
- **"练 1 题"入口常驻**。任何时候都能做一题就走，不进入会话流程（不弹结算页，进度照常落库）。这是最高频的低摩擦入口。
- 首页主按钮文案随账号年龄变化：首次"开始（约 4 分钟）"，之后"继续（约 12 分钟）"。**明确告知时长**比事后让人放弃好。

### 落点

`assets/rules/session_plan.md`

### 验证

| 指标 | 目标 |
| --- | --- |
| 首会话完成率 | > 70% |
| 首会话后 24 小时内有第二次训练的比例 | > 40% |
| "练 1 题"入口的使用占比 | 可观测，应 > 10% |

## P1-4 生词库会积压成负资产

### 问题

v2.2 §7 设计了标记→入库→补基础→升格的完整流转。但**没有设计积压**。

### 根因

**流入速度恒定，流出速度有限，而流入永远比流出快。**

用户每天标记 3–5 个生词，但每天只能练 12 题、其中升格生词最多占第 1 组（3 题）。第 2 周开始，生词库里堆着 30 个待补基础的词。而每个词都显示着"待补基础"的红色标签。

一个 30 项待办列表在用户心里的形象是**债务**，不是资产。他会开始回避打开生词库。

更要命的是 v2.2 §7.3-C 的结算汇报："标记生词 3 个 → 3 个待补基础"。**每天都报告自己欠了更多。** 这在第 3 周会变成明确的说服用户卸载的理由。

### 带来什么

1. 生词库从"最有价值的页面"变成"最有压力的页面"，用户主动回避。
2. 结算页的生词汇报从正反馈变成负反馈——这是设计错误，不只是文案问题。
3. 被标记的词长期得不到训练，标记动作的价值无法兑现，**反过来摧毁标记意愿**（"我标了也没用"）。

### 对策

**一、给生词库设上限和出口。**

- **活跃生词上限：40 个**。超出时，标记不再新增，而是把**最早标记的生词**重新排入目标训练队列。
- 即：标记 = **插队**（"你优先练这个"），不是**累加**（"你又多欠了一个"）。

这个转换很关键。插队模型下，标记 100 个和标记 10 个的收益是"优先级提升"，而不是"负债累积"。

**二、生词汇报改为成就导向。**

| 不推荐 | 推荐 |
| --- | --- |
| 标记生词 3 个 → 3 个待补基础 | 标记 3 个生词，其中 2 个已排入明日训练 |
| 待补基础 27 个 | 优先练这 8 个（其余已排期） |
| （无） | 本周攻克 6 个生词 |

**永远不报告"你还有多少没做"，只报告"你已安排了什么"和"你完成了什么"。**

**三、允许放弃。**

生词库提供"这些词我其实认识"和"清空已完成"的操作。**没有出口的列表必然被逃避。**

### 落点

`assets/rules/word_bank.md` — 上限、插队算法、汇报文案模板

### 验证

| 指标 | 目标 |
| --- | --- |
| 生词库周访问量 | 应稳定，不应随时间衰减 |
| 生词库平均积压量 | < 25（40 上限的 60%） |
| 标记生词后 7 天内被训练到的比例 | > 70%（低于此说明插队机制失效） |

## P1-5 进度不可感（同 P0-4，此处只列 UI 侧）

### 问题

进度有了（v2.2 §12.4），但**呈现方式让人无感**。

### 根因

v2.2 §12.4 定的三个数字：`已练义项数 / 已掌握义项数 / 待补基础生词数`。

- "已练 380 个义项"——不知道 380 是好还是坏
- "已掌握 120"——不知道花了多久、值不值
- "待补基础 27"——压力（见 P1-4）

全是**存量指标**。存量指标的问题：每次看都一样，或者只涨不反映真实能力。**用户无法从中读出"我的能力在变强"。**

### 带来什么

用户在第 3 周打开进度页，看到"已练 380 / 已掌握 120"，和第 1 周的"已练 60 / 已掌握 12"相比，比例差不多（20% vs 20%），感觉是"我在重复同一件事"。

### 对策

**首页与进度页必须回答三个不同层次的问题：**

| 层次 | 问题 | 指标 | 来源 |
| --- | --- | --- | --- |
| 我在推进吗 | 距考试还有几天，今天该练多少 | 倒计时 + 今日进度环 | P0-2 |
| **我记住了吗** | **上周学的词现在还记得多少** | **留存曲线** | **P0-4** |
| 我变强了吗 | 上周正确率 vs 本周正确率 | 趋势对比（不是绝对值） | 新增 |

**趋势优先于存量**。显示"本周 76%，上周 68%"比"累计 71%"有用得多，因为它证明了能力在变。

**今日进度环要显示"超额"**（"今日 12/12 · 已超额"），不要显示"还差 8 题"。这与 P1-4 是同一个原则：给完成的正反馈，不给欠账的负反馈。

### 落点

`assets/rules/progress_display.md` — 指标定义 + 展示优先级 + 文案模板

# 第三部分：P2（规模与内容质量）

## P2-1 义项切分标准未定义，但考研释义表已经给了答案

v2.2 §16 曾把"义项颗粒度"列为最关键的未决项。**定向考研后，这题不需要我们自己定义答案。**

**对策**：直接采用考研大纲释义表的义项切分。理由：
1. 这是考试的标准，用户不需要理解我们的切分逻辑
2. 与真题的考查点天然对齐
3. 免费获得（大纲附件是公开文件）
4. 切分歧义消失——以前"run 该切几个义项"是开放问题，现在答案是"大纲给了几个就是几个"

**衍生设计**：大纲释义表通常按"常见→次见"排序。**排在第 2 位及以后的义项是考研陷阱位**（"address 处理"而非"地址"，"issue 问题"而非"发行"）。训练卡应优先覆盖这些义项，且 **M2 二义辨析应优先用"第 1 位 vs 第 2 位"**——这正是用户最容易滑过去的地方。

## P2-2 7 万句的生成与存储，规模上是否可行

| 项 | 估算 | 结论 |
| --- | --- | --- |
| 训练卡 | 5500 词 × 平均 2.5 义项 ≈ **13,750** | — |
| 例句 | × 5 句 = **约 69,000** | — |
| 仅 L3 质检后的入库量 | 假设 60% 通过 ≈ 41,000 | 优先保证真题覆盖义项 |
| 语料侧 | 考研真题约 20 年 × 4 篇 × 400 词 ≈ **32,000 词** | **只够覆盖约 1000–2000 个义项** |

**这是关键约束**：真题量不足以覆盖全部 13,750 个义项。

**对策：分层供给**

| 层 | 义项来源 | 句子来源 | 覆盖目标 |
| --- | --- | --- | --- |
| **T1 真题层** | 真题中真实出现的义项 | 真题原句 + AI 拆句 | 全部（100%），这是训练价值最高的部分 |
| T2 大纲层 | 大纲全部义项 | AI 生成 + 独立质检 | 全部 |
| T3 补充层 | 导入词书 | AI 生成 | 按需 |

**排布时优先 T1。** 用户的核心诉求是"我在真题里见过的词都能判别"，这个必须做到 100%。T2/T3 是覆盖率补充。

**同时这个发现给出了一个更强的产品定位**：

> 不是"5500 词的背单词软件"，而是"**历年考研真题词汇的判别训练器**"。

前者是通用价值（打不过墨墨、百词斩），后者是垂直且难以替代的价值（墨陌/扇贝都不做"在句中判别义项"）。**P2-2 的算术直接推翻了"通用 5500 词"这个定位**，值得单独确认。

## P2-3 生成质量无法自动评估

v2.2 §8.5 只有人工抽检（5%）。69,000 句抽检 5% = 3,450 句，人工不现实。

**对策：质检器本身要被评估。**
- 维护一个**黄金集**：50 个义项 × 3 句 = 150 句，人工逐句标注"有效/无效"
- 每次质检器 prompt 变更，跑黄金集，报告一致率
- 一致率 < 85% 的质检器版本不允许上线（CI 卡住）
- 这让"质检器质量"变成一个可回归的工程指标，而不是玄学

## P2-4 干扰项策略在考研场景需要反转

v2.2 §3 定了"干扰项优先同形不同义"。在考研语境下**方向一致但主次要调**：

- 考研词汇本质是**熟词僻义**，"意外义项"是主角而非配角
- 但若只练意外义项，用户会觉得"这词我明明认识，题目在为难我"，且违反信号可辨识原则
- **对策**：一个单词的多个义项**轮换成为目标**，保证每类都练到。但 M2 辨析形态**优先用"大纲第 1 位 vs 第 2 位"**，因为这是最易滑过的组合

## P2-5 阶段化词书需要自动切换

P0-2 的阶段模型要落到具体的词书子集：

| 阶段 | 目标词书 | 新义项/日 | 复习占比 |
| --- | --- | --- | --- |
| 基础期 | `kaoyan_core_2500` | 8 | 20% |
| 强化期 | `kaoyan_dagang_5500` | 10 | 50% |
| 冲刺期 | `kaoyan_essay_800` + 高错词 | 4 | **80%** |

冲刺期复习占 80% 是关键：**考前 3 个月最重要的事是把已学的记住，不是学新的。** 这个比例变化应该明确告知用户，否则他会觉得"怎么都不给我学新词了"。

# 第五部分：这些修正引出的新问题

回答完上面的问题之后，暴露出下一层的问题。**这一栏是下一轮的工作项。**

## N1 训练材料中 AI 生成的部分（占比可能过半），P0-1 的方差问题并没有被完全消灭

L1（真题）只覆盖 1000–2000 个义项，剩下 11,000+ 义项还是 AI 生成。这些部分的方差依然会污染 SRS。

**要问的问题**：是否应该**放弃覆盖全部 13,750 个义项**，只做真题覆盖的那 1,000–2,000 个？

- 支持放弃：覆盖 1,000 个高频真题义项的实际效用，可能高于 13,750 个里的大部分低频义项。**深度 > 广度**。
- 支持全量：用户会问"我大纲里的词都能练吗"，缺了会流失。
- 这是一个**产品定位级别的取舍**，比任何技术决策都重要。见 N5。

## N2 留存曲线的诚实性 vs 好看

"上周学的词还记得 84%"——这个数字很打动人，但它完全取决于**复习时机的算法**。如果复习太密集，数字会虚高（90%+），用户觉得好，但实际记忆强度没提升。

**要问的问题**：留存曲线应该**强制只在到期复习时计算**（诚实但数字难看，约 60–70%），还是允许用早复习拉高数字（好看但骗人）？

我的判断是诚实优先——**曲线难看而真实，比好看而虚假更能建立长期信任**。但要确认产品愿意接受首屏显示"68%"而不是"89%"。

## N3 保留练过的痕迹 vs 减法做得太干净，验证感就消失了

考研用户会做真题。**如果我们的判别训练和他的真题练习割裂开，两边互相削弱。**

**要问的问题**：能不能把真题练习本身也变成训练入口？
- 用户在做真题时标记不认识的词 → 直接进高优先级训练队列
- 这让产品的训练内容与用户的实际备考行为对齐，而不是平行运行两套东西

这是 v2.1 §5.3"升格为目标词"的最强形态，但需要一套真题练习的集成方案，是 v1.5+ 的范围。

## N4 没有服务端，生成流水线和质检跑在哪

P0-1 的双 pass 质检 + P0-3 的热更新都需要"某处持续运行"。如果没有服务端：

- 生成/质检：只能在**用户设备上**跑 → 用户手机承担 69,000 句的生成，耗电、发热、耗流量，且只有活跃用户会触发，**长尾义项永远生成不出来**
- 内容更新：需要"某处"发布 assets bundle → 最低限度需要**一个极简的内容服务**（只存 bundle，不存用户数据）

**要问的问题**：这个"极简内容服务"要不要做？它不只是分发，还是**全量生成与质检的唯一执行环境**（一次跑完，产出 bundle 下发给所有用户）。

这可能是整个项目**唯一必须存在的服务端**，且它反而是内容质量的保障。绕不开。

## N5 如果定位改成"真题词汇判别训练器"，那 T2 通用层还要不要

若采纳 N1 的"只做真题覆盖"，T2（AI 生成 11,000 义项）的投入产出比会变得很差——它是成本大头，但价值低。

**要问的问题**：产品是
- **A. 垂直聚焦**：只做真题词汇 1,000–2,000 义项，做深（每义项 8–10 句、多形态、人工精校）→ 小而美，留存高
- **B. 全量覆盖**：13,750 义项都做，靠自动化质检维持质量 → 大而全，运营成本高，与其他背词 App 同质化

我倾向 A。但 A 会让"5500 词"这个数字消失，与用户预期不符，需要在产品表达上解决（"我们只练真题考过的，但你练的每一个都练透"）。

## N6 断网训练是默认，但这与"内容要持续更新"矛盾

P0-4 定了训练不依赖网络（这是稳定性的关键）。但 P0-3 的内容热更新依赖网络。P0-1 的质检若在客户端跑也依赖网络。

**要问的问题**：一个"永远离线可训练"的产品，如何让用户感知到内容在变好？

- 可能需要一个"内容已更新"的低频提示（每周一次结算时）
- 或者接受"用户可能几个月不更新内容也不知情"——这在稳定性上可接受，在增长上不可接受

这是个真实的取舍，需要明确选边。

## N7 词库的"义项"数量膨胀，会让"掌握"变得不可达

13,750 个义项。假设用户每天有效训练 12 题，一年 365 天 = 4,380 题。即使全部有效，也只能覆盖 32% 的义项。**"掌握全部考研词汇"在数学上不成立。**

**要问的问题**：产品要不要**明确告诉用户这件事**？

- 诚实告知："一年后你大概能覆盖 30% 的义项，但覆盖到的部分你很扎实" → 用户预期合理，但可能显得进展慢
- 隐性处理：只显示进度百分比，不做总量对比 → 好看，但用户迟早会发现"学了半年怎么还是 20%"

数学上必须收敛。承认它，比假装它是 100% 更有说服力。

# 第六部分：方向重置（v2.3）

> 写入日期：第一轮决策记录完成后、第二轮自问期间。**以下记录随时间被推翻，保持原文以反映决策演变。**

## R-1 孤立的定位之争本身是惯性

### 问题

N5 把产品问成了"真题垂直聚焦 vs 全量大纲"二选一，并让用户选中了 A（真题垂直聚焦）。但追问到一个决定性事实后，这个二选一**根本不成立**。

> 用户原话：「其实我是给自己用的，是不是题无所谓，重点是学会。」

### 根因

我把一个**个人学习工具**问成了一个**面向千万用户的产品定位题**。真题垂直 vs 全量，是"用户增长、差异化、留存"语境下的题。个人用的意义只有一条：**能不能让我学会。**

真题有价值，但它只是手段：真题句子质量高、信号真。可手段必须为效果服务——如果纯生成 + 质检能达成同等信号质量、且维护成本更低，真题就不是必需品。

> 用户原话：「你可千万不要背惯性思路带沟里去，我只要效果。」

### 带来什么（如果我并没有自我纠正）

1. 为了"真题垂直"会去建设真题文本管线、处理版权、做真题年份切分——大量投入，产出只是"句子更像真题"。
2. 为了"全量覆盖"会去生成 13,750 个义项、69,000 句，其中过半低频词训练价值很低。
3. 两者都是**产品的惯性**，不是**学习者的需要**。对单个学习者，正确答案永远是压缩成本、专注效果。

### 对策（既定方向）

**定位一句话**：一个给自己用的、可编辑的考研词汇判别训练器。

- **不需要**：账号、留存、增长、词书切换、真题词书、考试日期、阶段、倒计时、个性化推荐。
- **需要**：内容质量、稳定性、可编辑、可导出、可离线、判分正确、界面克制美观。
- 范围分层：**默认核心 3000 词做透，可配置扩充到全量 5500**（用户已选"可配置分层"）。低频词的例句质量必然下降——这是数学，不是实现失误，用高频词的高质量兜住体验。

## R-2 N4 的服务端决策也被同一惯性推翻

N4 的问题是"生成/质检跑在哪，没有服务端长尾义项生成不出来"。但个人场景下：

- 生成/质检是**开发机上的批处理脚本**，跑一次出 bundle，装进 App 后**永久离线**。
- 没有"一个想用但没用上的用户"需要填补长尾。覆盖规模=安装时的设置，一次性跑完。
- 服务端不存在。更新 = 换 bundle 文件。

## R-3 留存/漏斗型指标（P0-4、P1-3……）部分失效

个人工具没有"留存率""首会话完成率"。判分曲线、"连续 N 天"这类指标的意义只剩一个：**对学习效果的诚实反馈**。P0-4"留存曲线"改写为"复习正确率曲线"，只为一件事——让用户看到"我确实越记越牢"。

## R-4 真题从"地基"降级为"可选素材"

P0-1 L1"真题语料"从必须项降为可选项：若后续用户觉得生成句的语气不够真题味，再接真题增强。地基改为：**AI 生成 + 独立质检 + 用户纠错闭环**。

## D12 单义词策略（2401 个单义：80%）

现状：Stage1 产出 3642 义项 / 3000 词，599 词(20%)多义，2401 词(80%)单义（只有 1 个大纲义项）。

| 方案 | 结果 | 决策 |
| --- | --- | --- |
| 跨词干扰 | 题干句核心词多为同词多义，单义词插入做干扰项，不单独出题 | 部分采用 |

- 判别题平衡性：多义词卡 ≥ 599（覆盖全多义词）

- 选项组装无重复：无两个义项长得像（打包校验）

## D13 · 动态句子生成（防作弊，9/29）

### 问题

同一对子反复复习，用户必然背熟句子→答案的映射，之后"判别"退化为"认句子"。纯离线池（每义项 5 句）本质是换句防作弊，但池耗尽或用户标"有毛病"后无解。

### 决策

**混合：离线池优先 + 运行时按需生成兜底（D13）。**

1. 主体不变：Stage 2 离线生成每义项 5+ 句（3 用 2 备），App 离线消费。
2. 运行时生成**只触发两情形**：义项句池耗尽 或 用户点「这题有毛病」。
3. 触发即对该**单个对子**调 DeepSeek 生成 1 句，异步后台、不阻塞当前卡。
4. 仅联网触发；离线静默退化为"复用已答句洗牌兜底"。

### 理由

- 每次现生成（方案 A）防作弊最强，但每题等 2-3s 打断手感，且无限烧 token。
- 纯离线池（方案 B）成本零，但 5 句仍可能被背熟。
- 混合（方案 C）平时零延迟零成本（池内轮换），只在真正需要时现生成一次——平衡最优。

### 落点

- 规格 v2.4 §5.4（运行时按需生成）
- 运行时生成句 `source:LIVE` 单独标记，进入轮换但不重复

### 验证

- 池耗尽后能触发生成；生成的句子通过迷你质检（PASS/REJECT）
- 离线时无网络也能正常复习（兜底路径）


## D14 · 掌握判定兜底 + 错题板 + 小结页（9/29）

### 问题

1. 用户提了三条优化方向需要收敛：掌握判定（"连续对 10 次？还是手动标记？"）、聚焦真正不会的词、防冗体验。
2. 规格已有：答错→下一场自动复现（§7.1）。缺的是"用户可见的聚合视图"和"用户主动补强入口"。

### 决策（三件套）

1. **掌握判定**：保留现有 SM-2（interval≥3 且近3次全对且无 PENDING），**新增「我已学会」手动标记**兜底。不用"连续对10次"——同一对子一场只出现一次，对 10 次要跨 10 场，interval 拉长后实际 2-3 个月，等于永远学不完。
2. **错题板**：自动累积"判错/不会"的对子，按权重排序，**纯可见层不动排布**（排布仍由 §6/§7.1 复现规则负责）。点一项即"单挑"（不受排布制约）。
3. **小结页**：只在**完整走完一场（5/10/20）时弹**。极简 4 行（本场新学/对/错/不会 + 错过列表 + MASTERED 数）。「练1题」与随时停不弹，兼容 §7"轻结算"哲学。

### 理由

- 折中于"自动判定"与"个人自用"：算法负责被动照顾，用户手动负责主动补强。
- 错题板不做"答错3次置顶"的强制排布联动——两套机制抢同一批对子会让调度复杂化；个人自用，主观比算法准。

### 落点

- 规格 v2.4：§6 手动标记补充；§7.3 小结页；§8.1/§8.5 错题板（含排序权重与降级规则）

### 验证

- 完整场次结束弹出小结页；「练1题」不弹
- 错题板按 错多次>错一次>不会 排序；单挑后连续 2 对 → 降级移除
- 手动标记「我已学会」→ 该对子 MASTERED，未排期轮次跳过
